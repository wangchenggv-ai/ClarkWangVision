## 一、四张表的关系

```
06 市场会议管理（一场会 = 一条记录）
  ├── 07 会议签到记录（一个签到人 = 一条记录，扫码自动写入）
  ├── 08 会议酒店房量表（一个酒店 = 一条记录，实时看余量）
  └── 09 住宿订房记录（一间房的预订 = 一条记录，销售提交 → 你审核）
```

**一句话总结**：06管"会"，07管"谁来了"，08管"酒店有多少房"，09管"谁订了哪间房"。

## 二、06 市场会议管理

### 用途

管理所有市场会议，分为两层结构：
- **大会级**：如"COOC 2026上海"——父会议留空
- **子活动级**：如"4.9 新产品推广会"——父会议关联到"COOC 2026上海"

### 怎么用

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 新建记录，填写会议名称 | 大会级先建，子活动级后建 |
| 2 | 子活动填写"父会议" | link字段，关联到对应的大会 |
| 3 | 填写会议日期、会议类型、计划人数 | |
| 4 | 会议状态按进度更新 | 筹备中 → 进行中 → 已完成 → 已复盘 |
| 5 | 会后填写实际签到数、不重复机构数、总房间数、会议总费用 | |
| 6 | "会后30天出单额"由系统自动回填（rule7），无需手动填写 | |

### 字段说明

| 字段 | 说明 |
|------|------|
| 会议名称 | 必填，如"COOC 2026上海"或"4.9 新产品推广会" |
| 父会议 | 子活动填，大会留空 |
| 会议类型 | 五选一：学术年会/城市推广会/卫星会/代理商培训/自办会 |
| 负责销售 | 可多选，对应参会的销售 |
| 参会客户名单 | 自动关联，从07表签到匹配后同步，无需手动操作 |

## 三、07 会议签到记录

### 用途

每场会议一个扫码签到表单，参会者手机扫码填写后自动写入这张表。

### 操作流程

| 步骤 | 时间点 | 操作 |
|------|--------|------|
| 1 | 会前1-2周 | 在07表上为本次会议创建一个**签到表单** |
| 2 | 会前1周 | 从表单获取分享链接，生成二维码，发给销售用于邀约 |
| 3 | 会中 | 参会者到场扫码，填写姓名/手机号/单位/场次/感兴趣产品线 |
| 4 | 会后 | 数据已自动进入07表，运行匹配脚本关联到02表客户 |
| 5 | 会后 | 检查匹配结果，处理未匹配的记录（新建客户或修正匹配） |

### 创建签到表单

1. 打开07表 → 点击「+」新建视图 → 选择「表单」
2. 勾选需要填写的字段：姓名、手机号、单位名称、参会场次、邀请销售、感兴趣的产品线
3. 设置所有字段为必填
4. 获取表单分享链接，生成二维码

### 匹配逻辑（会后自动执行）

- 单位名称 → 模糊匹配02表客户名称
- 匹配到 → "关联客户"字段自动填入
- 未匹配 → 自动在02表新建客户（阶段=意向，来源=COOC 2026，数据状态=待审核）
- 同步更新06表该会议的"参会客户名单"

### 需要你检查的

- 匹配完后扫一遍记录，看有没有明显错误（如"视康"误匹配成"杭州明视康"）
- 手动修正错误匹配：修改"关联客户"link字段
- 未匹配到的老客户，手动关联

## 四、08 会议酒店房量表

### 用途

管理每场会议的酒店房间池，实时显示各房型剩余数量。

### 操作流程

| 步骤 | 时间点 | 操作 |
|------|--------|------|
| 1 | 确定酒店后 | 新建记录，填写酒店信息和房量 |
| 2 | 销售开始订房后 | 每确认一间房，对应房型"已订"+1 |
| 3 | 全程 | 关注剩余数量，及时协调加房 |

### 填写示例

```
酒店名称：上海XX酒店
酒店联系人：张三
酒店联系电话：138xxxx
大床房总量：20    大床房已订：0
双床房总量：30    双床房已订：0
入住日期：2026-05-15
退房日期：2026-05-18
所属会议：关联到06表对应会议
```

### 公式字段（自动计算，无需手动填写）

- **大床房剩余** = 大床房总量 - 大床房已订
- **双床房剩余** = 双床房总量 - 双床房已订

### 注意

- "已订"字段需要你**手动+1**（销售每确认一间，你更新一次）
- 如果同一场会有多个酒店，每个酒店建一条记录

## 五、09 住宿订房记录

### 用途

销售提交订房请求，你审核确认，完成订房闭环。

### 完整流程

```
销售扫码填表 → 09表生成记录（状态=待确认）
      ↓
你看到"待确认"记录
      ↓
确认时操作：
  ① 关联"所属会议"（link → 06表）
  ② 关联"关联酒店"（link → 08表）
  ③ 关联"客户名称"（link → 02表，如果能匹配到的话）
  ④ 状态改为"已确认"
  ⑤ 填入你的姓名（确认人）和确认时间
      ↓
去08表，对应酒店对应房型"已订"+1
      ↓
完成
```

### 订房表单

- 表单 ID：`vew8Hz37Vu`
- 销售填写字段：会议名称、酒店名称、入住客户、客户联系人、手机号、房型、入住日期、退房日期（8个必填）+ 备注（选填）
- 销售不需要填link字段，link字段由你在确认时手动关联

### 状态说明

| 状态 | 含义 | 下一步 |
|------|------|--------|
| 待确认 | 销售刚提交，等你处理 | 你去确认 |
| 已确认 | 你已审核，房间已锁定 | 无需再操作 |
| 已取消 | 取消预订 | 如果之前已确认过，记得去08表"已订"-1 |

### 取消处理

如果已确认的订单被取消：
1. 09表状态改为"已取消"
2. 去08表对应酒店对应房型"已订"-1

## 七、常见问题

**Q：销售忘记扫码签到，客户信息没进来怎么办？**
A：手动在07表新建记录，填写信息后关联客户。

**Q：08表的"已订"忘记+1了，怎么补？**
A：翻09表该酒店的"已确认"记录数，手动更新08表"已订"字段。

**Q：一个客户在07表签到了两次（两场子活动），会重复吗？**
A：不会，匹配脚本会识别同一单位，关联到同一个02表客户。

**Q：客户名称不确定怎么匹配？**
A：先留空"关联客户"，会后找销售确认后手动关联。

**Q：订房表单里的"会议名称"和"酒店名称"是文字，和06/08表的link不一致？**
A：这是正常的，销售填文字，你在确认时手动关联正确的link字段。
