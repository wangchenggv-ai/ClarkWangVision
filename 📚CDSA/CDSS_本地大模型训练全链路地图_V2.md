## 从病历到 CDSS 的完整流程

### 第一步：数据采集（正在做）

- 终端门诊录入患者数据到咏柳的专病管理系统
- 每个患者 5 个随访点：初诊 + 每 3 个月复查
- 核心字段：年龄、屈光度、轴长、角膜曲率、干预方式、镜片参数、依从性
- 目标：5000 例 × 5 次 = 25000 条记录
- **现有资产：已有 300 人完整病历数据（临床试验数据），可用于 RAG 测试**

### 第二步：数据清洗与标准化

- 脱敏处理（去姓名、身份证、联系方式）
- 字段统一（不同门诊的叫法和单位可能不同）
- 质量筛选（去掉缺失值 >30% 的病例）
- 转成标准格式：JSON 或 CSV
- **难度：中等，用 Claude 辅助就能做，主要是脏活**

### 第三步：构建训练数据集（关键更新）

#### 标注的本质

把"指令-回答"对写出来：输入是患者临床数据，输出是临床决策（评估 → 建议 → 理由 → 风险提示）。

#### V1 认知（已修正）

- ~~500 例标注由创始人亲自写~~
- ~~2-3 个周末可完成~~

#### V2 认知

- **500 例标注不是一个人能写的**，需要多中心医生基于真实病例协作完成
- **标注规范不该从零设计**，要找做过多中心 RWS / 临床试验、懂 CRF 设计的医生来主导
- **Clark 的角色**：定义业务需求（模型学什么决策、覆盖什么场景），做最终质量审核和高视星方案逻辑把关
- **500 例的来源**：20 个中心 × 每中心 25 例，在日常诊疗中自然积累

#### 咏柳软件 = 标注一体化工具（核心洞察）

咏柳病程管理软件现有功能解决了**输入端**（患者数据的标准化采集）。需要增加一个**"临床决策"模块**作为输出端：

- 进展评级（快速 / 中等 / 稳定）
- 当前方案评估（有效 / 需调整 / 无效）
- 建议方案（维持 / 升级 / 联合治疗）+ 具体产品选择
- 调整理由（下拉选项 + 自由文本）
- 风险提示

**设计原则**：尽量用下拉选项和结构化选择，减少自由文本，导出即为标准标注数据。

**实现路径**：
1. 找到标注规范设计者（做过近视防控多中心研究的临床医生）
2. 该医生定义决策模块的字段和选项
3. 咏柳开发该模块
4. 医生日常诊疗时顺手填写，标注成本趋近于零
5. 导出时自动拼接：患者数据（输入）+ 临床决策（输出）= 训练数据

#### 500 例够不够

500 不是硬门槛，是经验平衡点。验证方法：先画决策树，数核心路径数量，每条路径 5-10 例，反推总量。

### 第四步：选择技术路径

#### 路径一：RAG（先做，零训练成本）

- 不训练模型，把病历数据向量化存入 ChromaDB
- 查询时检索最相似的历史病例辅助回答
- PX13 本地完全能跑
- **白皮书也直接切块入 RAG**，作为行业共识层

#### 路径二：QLoRA 微调（数据验证后做）

- 500 例标注数据转 JSONL 格式
- 云端租 A100 跑 8-24 小时，10-45 美元
- 产出 LoRA 适配器文件，下载回本地合并
- **本地 RTX 4060（8GB）只够推理，不够微调**，必须上云或换 4090（24GB）

### 第五步：RAG 自动化 Pipeline

**已确认的自动化方案：**

```
咏柳导出新数据 → 飞书/文件夹 → OpenClaw 监听 → 调用 Python 脚本 → ChromaDB 更新 → 即时生效
```

脚本核心逻辑：接收 JSON/CSV → 文本化 → 切块 → 向量化 → 写入 ChromaDB。几十行 Python（LangChain + ChromaDB），几秒完成。

OpenClaw 职责：
- RAG 数据入库：全自动
- 微调批次管理：半自动（攒够 50 例新标注数据时提醒，人工确认后触发）
- 周报：每周汇总新增数据量和知识库总量

### 第六步：本地部署与验证

- RAG 方案：E4B + ChromaDB，PX13 完全能跑
- 微调方案：E4B + LoRA 适配器，Ollama 直接加载
- 验证方法：留 100 例不参与训练做测试集，对比方案准确率、安全红线、边界 case
- 节奏：**RAG 先上线验证产品逻辑，微调等 RAG 暴露"查不到、答不好"的场景后再针对性训练**

### 第七步：嵌入 CDSS 产品

- 包一层 Web 界面（vibe coding）
- 视光师输入患者数据 → 模型返回方案推荐 + 风险提示
- 医生审核确认 → 写入专病管理系统

## 关键判断（V2 更新）

- **两层架构**：白皮书喂 RAG（行业共识），医生标注喂微调（高视星特色）。两层叠加才是完整 CDSS
- **咏柳软件是枢纽**：加上决策模块后，一次诊疗动作同时产出训练数据的输入和输出，标注成本归零
- **标注规范设计是当前卡点**：需要找一个做过近视防控多中心研究、懂 CRF 设计的医生（CDSA 种子用户优先）
- **先 RAG 后微调**：RAG 零成本、实时更新、先验证产品逻辑；微调等 RAG 暴露短板后再做
- **本地只够推理，微调必须上云**：RTX 4060（8GB）跑不动训练，云端租 A100 单次 10-45 美元
- **RAG 全自动，微调半自动**：新数据入 RAG 无需人工干预；微调需要人工确认数据质量和验证效果
