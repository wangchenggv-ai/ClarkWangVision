# 高视星 · Track B 对外执行规划
## CDSA 临床数据联盟（终端视角：管临床）

> 服务合作门诊，驱动数据飞轮。
> 3 个系统是一个飞轮：CDSS 让门诊信任 → 专病管理让数据沉淀 → 运营仪表盘让门诊老板看到回报 → 更多门诊加入。

---

## 3 个系统现状

| 系统 | 定位 | 当前状态 |
|------|------|---------|
| CDSS Agent | 管得对 · 临床决策辅助 | 规划中，依赖数据积累 |
| 专病管理系统 | 管得住 · 患者随访 | 咏柳团队已交付，待部署 |
| 运营仪表盘 | 管得值 · 门诊运营分析 | 从零开始，依赖专病管理数据沉淀 |

---

## 依赖关系

```
专病管理系统（已交付）
    ↓ 采集病历、随访、复查数据
CDSS Agent
    ↓ 数据越多，决策建议越准
运营仪表盘
    ↑ 消费专病管理 + CDSS 的结果数据，呈现门诊价值
```

**优先级次序：专病管理首批部署 → CDSS 原型 → 运营仪表盘**

---

## 三阶段执行计划

### 第一阶段：4月下旬 - 5月中（4周）
**目标：专病管理系统首批落地**

| 任务 | 负责人 | 验收标准 |
|------|--------|---------|
| 在首批 3-5 家种子门诊完成部署 | 咏柳交付 / 市场总监落地 | 医生能独立录入病历，数据结构无误 |
| 部署 SOP 文档化 | Clark 定义 + 市场总监执行 | 流程、培训话术、数据检查清单成文 |
| 数据质量基线建立 | 市场总监 | 录入完整率目标 ≥ 70% |
| CDSS 不动，等数据 | — | — |

### 第二阶段：5月中 - 6月底（6周）
**目标：CDSS RAG 原型 + 专病管理扩展**

| 任务 | 负责人 | 验收标准 |
|------|--------|---------|
| 专病管理扩展至 10+ 家门诊 | 市场总监主导 | 数据量支撑 CDSS 训练 |
| 数据质量监控常态化 | 市场总监 | 每周检查完整率，< 70% 主动跟进 |
| CDSS RAG 原型开发 | Clark + Claude | 基于真实病历给出初步方案建议，可对外演示 |
| 运营仪表盘设计稿 | Clark | 核心指标和 UI 方案确定 |

**关键前提：** 此时已有 10+ 家门诊真实数据，CDSS 不再是空想。

### 第三阶段：7月 - 8月（4周）
**目标：运营仪表盘 MVP + CDSS V1 固化**

| 任务 | 负责人 | 验收标准 |
|------|--------|---------|
| 运营仪表盘 MVP 开发 | Clark | 患者 LTV、复购率、方案升级推荐核心看板上线 |
| 专病管理扩展至 20+ 家 | 市场总监 | 数据飞轮规模效应显现 |
| CDSS 持续迭代 | Clark | V1 临床逻辑固化，可向合作伙伴和投资方演示 |

## 角色分工

### Clark 负责
- CDSS 的产品定义、临床逻辑标注、技术实现（核心护城河，20 年 OK 镜经验，不可外包）
- 运营仪表盘编码
- 首次门诊拜访，输出 CDSA 价值主张

### 市场总监负责（终端落地全权）
- 专病管理在门诊端的部署和培训
- 数据质量监控（录入完整率 < 70% 主动催）
- 已签约门诊的日常维护和回访
- Clark 拜访完新门诊后，跟进签约和后续关系由她接管

### 咏柳团队负责
- 专病管理系统的 bug 修复和功能迭代
- 每周三 30 分钟与 Clark 对齐
- Clark 只管需求定义和验收，不碰代码
