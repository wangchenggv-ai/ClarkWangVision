# 马尼拉 实战辅助器

桌游 **Manila（Zoch Verlag, 2005, Franz-Benno Delonge）** 的实时辅助工具。

在真实牌桌对局时，把当前局面（船的位置、3 颗骰子、各玩家持股、自己的现金和角色等）手动输入界面，工具基于 Monte Carlo 概率模拟 + 多目标效用函数，给出每个决策点（船长骰子分配、买股、角色拍卖出价上限）的 **Top-N 推荐 + 决策分解**。

> 这不是一个完整的游戏，是一个**给真人玩家用的副驾驶**。

---

## 启动

双击 `start.bat`，浏览器自动打开 `http://localhost:8766/`。需要装了 **Python 3** 或 **Node.js**（其中之一）。

也可以用 Firefox 直接拖 `index.html` 进去（Chrome 因 ES module CORS 不行）。

---

## 决策模型

效用函数（你确认的三个维度）：

```
U(action) = ΔE[我方财富]
          - λ' · ΔVar[我方财富]      ← 风险/方差
          + α  · Δ(领先差距)         ← 领先/落后局势
          - β  · ΔE[最强对手财富]    ← 信息/对手抑制
```

- **λ' 动态调整**：领先时 ×1.5（更稳），落后时 ×0.5（更敢博）。
- 三个权重 λ / α / β 在右侧栏滑块可临场调。

## 概率引擎核心假设

`engine/probability.js` 用 Monte Carlo 模拟（默认 2500 样本）。建模假设全部集中在文件顶部注释，方便核对：

- **每阶段 3 颗骰子，每艘船分配一颗**（船长 6 种排列）；未指定时假设均匀随机。
- **海盗每阶段沉位置最低、未到港的船**（位置 ≥ 11 的船安全）。未来阶段保守假设海盗总有人持有。
- **已沉船**位置归 0、不再移动、不再被海盗选。
- **领航员/船坞主等加成角色暂未建模**——影响小，后续可在 `simulatePhase` 里加 hook。

## 规则常数（你**必须核对**）

`engine/rules.js` 顶部的常量是按 BGG 常见数据写的，但不同年份印刷版可能有差异。**对照你那本规则书改这里**：

| 常量                  | 含义                                       | 默认值                                |
| -------------------- | ------------------------------------------ | ------------------------------------ |
| `PAYOFF_PER_SHARE`   | 终局每股回报（按船的位置）                       | `{13:30, 12:25, 11:20, 10:15, 9:10, 8:6, 7:3}` |
| `STOCK_PRICE_TIERS`  | 每艘船 5 张股票的价格梯队（低→高）              | `[4, 8, 12, 16, 20]`                 |
| `DICE.faces`         | 骰子面（马尼拉用 1-3 点）                        | `[1, 2, 3]`                          |
| `HARBOR_POSITIONS`   | 安全港位置（在此沉不掉）                         | `[11, 12, 13]`                       |
| `TOTAL_ROUNDS`       | 总轮数                                       | `3`                                  |
| `PHASES_PER_ROUND`   | 每轮骰子阶段数                                  | `3`                                  |
| `ROLES`              | 8 个角色名称                                   | captain/pirate/pilot/harborMaster/speculator/loader/banker/insurance |

改完保存，浏览器刷新即生效（无需重启）。

## 用法（每阶段流程）

1. **首次进入**：填玩家人数、自己座位、玩家名。
2. **左栏**：调船的位置/存活，调玩家持股/现金，调股票市场剩余。
3. **右栏 - 当前阶段**：
   - 选 3 颗骰子的点数
   - 选本阶段每个角色被谁拿到（包括自己）
4. **右栏 - 推荐**会实时刷新：
   - **船长骰子分配** Top-3 + U 分解
   - **股票购买**（含"不买"基线）
   - **角色拍卖出价上限**（船长/海盗已建模，其他待补）
5. 决策完点 **「阶段结束 → 下一阶段」**，骰子和角色清空，进入下一阶段。

## 决策分解列含义

| 列      | 含义                                                |
| ------ | --------------------------------------------------- |
| **U**  | 总效用（按公式综合）                                   |
| ΔE     | 我方期望财富变化（金币）                                |
| ΔVar   | 我方组合方差变化（越大风险越高）                          |
| Δ领先  | 我和第二名差距的变化（>0 = 拉开了，<0 = 被追近了）           |
| Δ对手  | 最强对手期望财富变化（U 公式里取负 = 对手降了我反而开心）       |

## 已知限制

- **领航员、船坞主、装卸工** 等角色的加成动作未在概率引擎里建模；这些角色的拍卖估值标 `—`。后续可在 `probability.simulatePhase` 加 hook。
- **拍卖博弈** 是简化的"单回合估值"，没建模"对手出价对我加价的影响"。
- **海盗策略**：未来阶段假设总有人持有海盗；如果某场你预判海盗会流拍，这是对沉船率的高估（偏保守）。
- **MC 样本** 默认 2500，每次评估 ~30-100ms。如果机器慢觉得卡，可在 `advisor.js` 把 `MC_SAMPLES` 降到 1000。
