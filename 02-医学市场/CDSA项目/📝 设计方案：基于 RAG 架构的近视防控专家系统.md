

 1. 项目愿景 (Project Vision)

 构建一个“本地知识驱动 + 云端大模型大脑”的智能临床决策支持系统（CDSS）。利用有限的临床金标准数据（200例高价值病例），通过 RAG (Retrieval-Augmented Generation)
 技术，克服大模型的“幻觉”问题，提供具备医学循证依据的近视防控建议。

 2. 核心设计理念 (Core Philosophy)

 本方案舍弃了昂贵且困难的“全量模型微调 (Fine-tuning)”，采用 “小数据驱动、大模型推理” 的混合架构：
 - 本地化知识库 (Local Knowledge Base)：存储具有临床价值的病例、诊疗指南、药物参数及专家经验。
 - 云端智能大脑 (Cloud Intelligence)：作为逻辑推理引擎，负责理解复杂的医学语义、进行医学逻辑演绎和语言生成。
 - 检索增强生成 (RAG)：通过检索本地证据并将其注入 Prompt，确保模型的输出“有据可查”。

 3. 系统架构 (System Architecture)

 系统分为三层逻辑结构：

 ### 3.1 知识层 (Knowledge Layer) — "医学灵魂"

 - 数据形态：结构化病例（年龄、度数、轴长、角膜曲率）、非结构化文本（医生诊断意见、随访记录）、医学文献（最新的临床指南）。
 - 数据处理：
     - Chunking (切片)：将长文档按医学逻辑（如：按“诊断-检查-治疗-随访”模块）进行语义切片。
     - Embedding (向量化)：使用医疗专用 Embedding 模型（或高性能通用模型）将文本转化为多维向量。
     - Indexing (索引)：存入向量数据库。

 ### 3.2 检索层 (Retrieval Layer) — "信息桥梁"

 - 语义检索 (Semantic Search)：利用向量相似度匹配用户查询与知识库内容。
 - 混合检索 (Hybrid Search)：结合 关键词检索 (BM25) 与 向量检索 (Vector)，确保既能匹配具体的医学术语（如“散光度数”），也能理解模糊的语义（如“视力下降严重”）。
 - Reranking (重排序)：使用重排序模型对初筛结果进行二次评估，确保最相关的医学证据排在 Prompt 的最前面。

 ### 3.3 推理层 (Inference Layer) — "医学大脑"

 - Prompt Engineering (提示词工程)：构建包含 [上下文证据] + [临床任务指令] + [医学约束条件] 的结构化提示词。
 - LLM 驱动：利用 GPT-4o 或 Claude 3.5 等超大规模模型，基于检索到的证据进行逻辑推理、风险预警和方案生成。

 4. 标准工作流 (Standard Workflow)

 5. 用户输入 (Input)：医生或患者输入临床问题（例如：“患者 8 岁，近视 200 度，轴长增长过快，该如何调整方案？”）。
 6. 查询转换 (Query Transformation)：系统将原始问题转化为更适合检索的医学标准术语。
 7. 检索匹配 (Retrieval)：从向量数据库中检索出最相关的 3-5 个历史病例及相关的临床指南条目。
 8. 上下文构造 (Context Construction)：将检索到的文献和病例拼接到 Prompt 中。
 9. 模型推理 (Reasoning)：LLM 读取证据，执行任务。
 10. 生成响应 (Response)：输出结构化的诊疗意见，并明确标注引用来源（例如：依据病例 A，建议……）。

 12. 风险控制与医学伦理 (Risk & Ethics)

 - 幻觉抑制 (Anti-Hallucination)：在 Prompt 中强制要求：“如果检索到的上下文中没有相关信息，请诚实回答不知道，严禁编造数据。”
 - 溯源机制 (Traceability)：每一条输出建议必须附带引用来源的索引（如 [Source: Case 012]），方便医生校验。
 - 医学免责 (Disclaimer)：系统输出结果应明确标注：“本建议仅供临床参考，不作为最终医疗诊断依据，请结合临床实际情况决策。”
 - 隐私保护 (Privacy)：在构建本地知识库前，必须进行 De-identification (脱敏处理)，删除所有患者姓名、身份证号等个人敏感信息 (PII)。
