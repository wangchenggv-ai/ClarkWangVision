### 关键架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 数据库 | 飞书 Bitable（无自建DB） | 零运维，业务团队可直接维护数据 |
| 后端 | Node.js 原生 http（无 Express） | 最小依赖，零构建 |
| 前端 | 原生 HTML + JS（无框架） | 零构建，单文件页面 |
| 表ID管理 | shared/tables.js 单一真相源 | 消除硬编码，改一处全局生效 |
| 库存粒度 | 度数级 (SKU × SPH × CYL) | 精确到片，支撑实时交期 |

| # | 名称 | 类别 | 说明 | 参数化 |

| 5 | 毛坯库存预警 | 库存 | 上游物料告警 | ✅ |
| 6 | 订单超期预警 | 订单 | 超时未处理告警 | ✅ |
| 7 | 采购自动触发 | 生产 | 毛坯/模芯低于安全线→采购 | ✅ |
| 8 | 排产分配车房 | 生产 | 按专长分配生产任务 | ✅ |
| 9 | 模芯使用累加 | 生产 | 完成→模芯已使用+1 | ✅ |
| 10 | 寄售到期预警 | 库存 | 60天黄/90天红+写流水 | ✅ |
| 11 | 月度对账单 | 库存 | 每月1-3日自动生成 | ✅ |

## 八、架构评价

### 优势

1. **零构建，极简栈** — Node.js 原生 + 飞书 Bitable，无 DB 运维，部署简单
2. **单一真相源** — shared/tables.js 消除硬编码，改一处全局生效
3. **规则引擎参数化** — 14条规则全部可调，业务用户可在飞书直接改参数
4. **数据飞轮** — 订单数据自动测算备库分布，越用越准
5. **端到端闭环** — 从下单到消费者验真，全链路可追踪

### 需关注

1. **server.js 体量** — ~2500行单文件，当前可维护，但持续增长需考虑拆分
2. **Bitable 作为数据库** — 适合当前规模（日单量~70），千级以上需评估性能
3. **无自动化测试套件** — 有E2E测试脚本但未纳入CI，回归靠手动跑
4. **预测数据缺失** — rule4 排产依赖人工录入周度预测，尚未实现自动化

### 总体判断

系统架构**合理且务实**。以飞书 Bitable 为底座，用最小技术栈实现了完整的业务闭环。
规则引擎是亮点——14条规则覆盖订单→库存→生产全链路，且全部参数化，业务可自调。
下一步重点应从"功能开发"转向"数据驱动"：让预测、备库、排产真正跑在真实数据上。
