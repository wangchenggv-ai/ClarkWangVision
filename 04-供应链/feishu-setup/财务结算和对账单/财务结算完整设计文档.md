# 代理商财务结算体系完整设计文档

> 版本：v1.0 | 2026-05-22
> 原则：飞书原生视图承担所有操作界面，Node.js只做飞书做不了的逻辑
> 计划：苏州回来后立项，约1周

---

## 一、整体逻辑框架

```
代理商专属定价表（飞书）
       ↓
下单时锁价（飞书公式）→ 预存款扣减（飞书自动化）
       ↓
签收确认（顺丰webhook / 7天自动签收）
       ↓
退换货冲销（飞书登记表 + 赋码API）
       ↓
季度返利计算（飞书视图手动确认）
       ↓
对账单（飞书筛选视图导出）
```

---

## 二、价格体系

### 2.1 定价表结构

```
代理商定价表（agent_pricing）
- 代理商ID
- 产品型号（SKU）
- 单价
- 拼接key = 代理商ID & "-" & 产品型号（公式字段）
```

每个代理商×每个产品型号一条记录，不同代理商价格不同，同一代理商不同型号价格不同。

### 2.2 下单时锁价（关键设计）

下单时将当前单价快照写入订单行，与定价表解耦，后续改价不影响历史订单：

```
订单行字段：
- 产品型号
- 数量
- unit_price（查找定价表，下单时锁定）
- amount = 数量 × unit_price（公式字段）
```

查价逻辑（飞书双条件匹配）：
```
定价表：key = 代理商ID & "-" & 产品型号
订单表：查找key → 匹配 unit_price
```

## 三、预存款体系

### 3.1 表结构

```
预存款流水表（agent_deposit_log）
- 代理商ID
- 类型：recharge / deduct / rebate_apply / return
- 金额（正数入账，负数扣款）
- 关联订单号
- 操作人
- 时间

代理商表：
- 预存款余额 = 汇总字段（从流水表实时计算）
```

### 3.2 下单扣减逻辑

```
操作员选代理商 → 订单表显示：
  当前余额：XXXXX 元
  本单金额：XXXXX 元
  下单后余额：XXXXX 元  ← 公式字段，负数显示红色预警

操作员确认提交
  → 飞书自动化：流水表写入一条 deduct 记录
  → 余额汇总字段自动更新
```

> 内部操作员下单，不存在并发问题，余额预警靠操作员人工判断，不做系统拦截。

### 3.3 充值流程

```
代理商打款 → 财务手工在流水表录入 recharge 记录 → 余额自动更新
```

### 3.4 边缘场景处理

| 场景 | 处理方式 |
|------|---------|
| 订单取消 | 手工录入 return 记录，金额退回，关联原订单号 |
| 部分发货 | 按实际发货金额扣，差额退回，写流水 |
| 余额不足 | 下单后余额红色预警，操作员不提交，人工通知充值 |
| 价格调整 | 只改定价表，历史订单 unit_price 已锁死不受影响 |

## 四、签收与自动签收

### 4.1 签收规则

- 签收日期作为计入对账单的时间维度
- 顺丰 webhook 触发自动签收
- 发货后 **7天** 无 webhook 则系统自动签收

### 4.2 自动签收逻辑（Node.js，~50行）

```javascript
// 每日凌晨执行定时任务
// 查询状态=已发货 且 发货时间 < 今天-7天
// → 批量更新状态为已签收，写签收时间
```

## 五、退换货管理

### 5.1 退换货登记表（飞书，零代码）

```
- 日期
- 原订单号
- 代理商
- 产品型号
- 眼别：左 / 右 / 双
- 类型：退货 / 换货
- 原因：质量问题 / 验光问题 / 下单错误
- 责任方：公司 / 代理商 / 分担
- 退款金额（0=公司承担免单）
- 处理人
- 备注
```

### 5.2 退款金额处理规则

| 责任方 | 处理方式 |
|------|---------|
| 责任在代理商 | 退款打回预存款，流水表记 return |
| 责任在公司 | 免单，流水表不动，登记表留记录 |
| 分担 | 各记各的部分 |

### 5.3 换货赋码逻辑（Node.js，~100行）

换货本质是**退货+重新生产**，必须赋新码：

```
POST /api/admin/exchange-order
  输入：原订单号 + 眼别（左/右/双）
  动作：
    旧码 → 状态=void，备注换货新码
    新码 → 正常赋码，备注原订单号
    写退换货登记记录
    触发重新生产流程
```

### 5.4 镜片码作废字段（lens_detail表新增）

```
- 镜片码状态：active / void
- 替换码（换货时填入新码）
- 关联退换货单号
```

### 5.5 溯源链

```
消费者扫新码 → 显示：换货镜片，原订单XXXX
消费者扫旧码 → 显示：已作废，换货码为XXXX
```

### 5.6 单片 vs 双片换货

| 场景 | 处理 |
|------|------|
| 双片换 | 两片旧码均 void，各赋新码 |
| 单片换 | 仅换货眼旧码 void，另一片保持 active 不变 |

## 六、季度返利体系

### 6.1 返利规则

- 统计维度：该代理商**所有型号合计签收量**
- 触发条件：季度合计达到门槛数量
- 兑现方式：**下季货款抵扣**，不现金返还
- 确认方式：手动 review 后确认，不做全自动

### 6.2 表结构（飞书，零代码）

```
返利规则表
- 代理商ID
- 季度发货量门槛
- 每件返利金额

返利记录表
- 代理商ID
- 季度（如 2026Q2）
- 合计签收量（公式汇总）
- 应得返利金额（公式：合计量 × 每件返利）
- 状态：待确认 / 已确认 / 已抵扣
- 抵扣目标季度
```

### 6.3 季末操作流程

```
季末：
  核对合计签收量（含退货调整）
  → 飞书直接改状态为已确认
  → 手工在流水表录入 rebate_apply 记录
  → 下季对账单自动包含此抵扣
```

> 手动确认防止季末退货数据未调整导致错误。

## 七、对账单

### 7.1 对账单结构

```
XX代理商 2026年Q3对账单

订单明细：
  订单号 / 型号 / 数量 / 单价 / 金额 / 签收日期

货款小计：        XXXXX 元
退货冲销：        -XXXX 元
返利抵扣（Q2）：  -XXXX 元
本期实付：        XXXXX 元
预存款余额：      XXXXX 元
```

### 7.2 金额计算逻辑

```
货款小计 = Σ（签收订单 数量 × unit_price）
退货冲销 = Σ（本期退换货登记 退款金额）
返利抵扣 = 上季已确认的 rebate_earned
本期实付 = 货款小计 - 退货冲销 - 返利抵扣
```

### 7.3 实现方式（飞书筛选视图，零代码）

按代理商+签收日期范围筛选订单视图，底部汇总行显示各项合计，导出 Excel 发给代理商。

### 7.4 确认机制

- 以我方数据为准
- 代理商有异议→人工沟通
- 无异议→我方操作员在飞书标记 confirmed

## 十、关键设计原则

| 原则 | 说明 |
|------|------|
| 锁价 | 下单时快照单价，与定价表解耦 |
| 流水制 | 预存款所有变动必须有流水记录，余额不直接维护 |
| 签收为准 | 以签收日期计入对账单，7天自动签收兜底 |
| 手动确认返利 | 季末数据可能有调整，不做全自动 |
| 够用就好 | 现阶段手工+飞书，规模大了再升级 |
