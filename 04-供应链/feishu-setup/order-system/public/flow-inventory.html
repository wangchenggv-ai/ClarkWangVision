StockResolver — 库存判定

lib/stock-resolver.js
输入lenses: [{sku, sph, cyl}]
输出[{stock, reserved, available, inStock}]
依赖: getStockMap() 缓存（2min TTL，O(1) 查找）
特点: 不关心库存结果意味着什么状态
→

StateRouter — 状态路由

lib/state-router.js
输入stockResults: [{inStock, inRange}]
输出{targetStatus, wfStep, deliveryType}
依赖: 无（纯函数，零 I/O）
特点: 不关心库存数据怎么来的
两模块互不知道对方存在，仅通过 {inStock: bool} 一个字段连接

lib/stock.js — 库存核心

lib/stock.js (247行)
getStockMap()全表缓存（1575行, 2min TTL）— 供 StockResolver 读
queryStockByRx()单记录过滤查询 — 供写操作锁内 fresh read
reserveStock()下单预占: withLock + fresh read + PATCH 预占+=qty
convertReservation()发货实扣: 库存−1 + 预占−1 原子写入
releaseReservation()退回释放: 预占 −= toRelease
estimateDeliveryByRx()交期预估: 三档判定（有货/排产/定制）

server.js — API 端点

server.js (4400行)
POST /api/submit写订单 → reserveStock() 预占
POST /api/admin/confirmresolveStock() → routeConfirm() → 写状态
POST /api/admin/shipconvertReservation() → 写物流 → 发通知
POST /api/admin/revert退状态 → releaseReservation() 释放预占
POST /api/admin/procurement创建成品采购单 → procurement 表
POST .../procurement/:id/receivewithLock → 库存+N → stock_movement 入库流水
GET /api/admin/stock-detail库存列表 + 预占/可用 + SKU 汇总

并发安全：withLock 每键互斥锁

key = "SKU编号|SPH|CYL"  →  Promise 链序列化同一度数的并发写
锁内流程：fresh GET 单条 → 计算新值 → PATCH 写入 → clearCache
防 lost update：两个并发请求写同一度数不会互相覆盖
