## 二、架构决策

**路径选择：路径B**
- 飞书多维表格：库存录入和展示（仓库人员操作）
- Node.js：业务逻辑和数据同步
- 理由：现有投入不浪费，仓库人员无需学习新工具

**混合库存逻辑（定制品）：**
```
下定制订单
→ 查成品SKU库存
  → 有库存：直接扣减，完成
  → 无库存：查毛坯库存
    → 有毛坯：生成车房生产指令，扣毛坯
    → 无毛坯：采购预警，人工处理
```

**注塑品：** 直接管理成品SKU库存，逻辑简单。

**模芯管理：** 手工管理足够，不上系统。

## 六、核心原则

1. **范围不收敛，630一定逾期** — 发现新需求一律记录，不实现
2. **写代码前先写业务逻辑** — 输入/输出/异常，写不清楚不动手
3. **对账最后做** — 它依赖所有上游数据的准确性
4. **仓库界面必须极简** — 操作者不是技术人员，容错要高
5. **文档是交接的前提** — 没有文档，接手成本极高

## 七、开发节奏建议
