# 工厂导出 Excel 排序问题 - 归因与修复

> 日期：2026-04-29

---

## 现象

订单管理中心导出"Excel给工厂"时，同一客户多副镜片排序错误：

```
❌ 错误：所有右眼排一起，所有左眼排一起
Clark 右眼 D8
Clark 右眼 Ultra双效
Clark 左眼 D8
Clark 左眼 Ultra双效

✅ 正确：每副右→左配对
Clark 右眼 D8
Clark 左眼 D8
Clark 右眼 Ultra双效
Clark 左眼 Ultra双效
```

---

## 根因分析

### 1. 序号语义错误（根本原因）

`pairIndex`（序号）的生成逻辑：

```js
// server.js line 281（修复前）
const pairIndex = patients.filter(p => p.customerName === name && p.sku === productModel).length + 1;
```

按 `顾客姓名 + 产品型号` 计数。Clark 买 D8 → 序号=1，买 Ultra双效 → 序号也是 1（SKU 不同，计数重置）。

**结果**：同一客户不同 SKU 的序号都是 1，无法区分不同副。

### 2. 排序逻辑缺陷（直接原因）

`lib/factory-export.js` 和 `server.js` 的排序只有 3 级：

```
顾客姓名 → 序号 → 眼别
```

当序号全部为 1 时，排序直接落到"眼别"比较，所有右眼排一起。

---

## 修复方案

### 修复 1：序号全局递增

`server.js` 行 281，去掉 SKU 过滤条件：

```js
// 修复前
const pairIndex = patients.filter(p => p.customerName === name && p.sku === productModel).length + 1;

// 修复后
const pairIndex = patients.filter(p => p.customerName === name).length + 1;
```

- Clark 第1副 → 序号1，第2副 → 序号2
- 不再因 SKU 不同而重置

### 修复 2：排序增加产品型号分组

`lib/factory-export.js` 和 `server.js`，排序扩展为 4 级：

```
顾客姓名 → 序号 → 产品型号 → 眼别 → 原始索引（稳定兜底）
```

| 级别 | 字段 | 作用 |
|------|------|------|
| 1 | 顾客姓名 | 按人分组 |
| 2 | 序号 | 按第几副分组 |
| 3 | 产品型号 | 同序号时按 SKU 分组（兜底历史数据） |
| 4 | 眼别 | 每副内右眼在上、左眼在下 |
| 5 | 原始索引 | 稳定排序，防止同等条件打散 |

### 修复 3：导出按钮恢复始终可见

`public/orders.html` 行 623，"导出Excel给工厂"按钮误加了 `ctx-btn` 类（默认隐藏），改为始终显示。

已有订单的序号仍为 1（Bitable 无自动迁移），但排序第 3 级"产品型号"兜底保证导出正确。新订单序号全局递增，排序完全正确。
