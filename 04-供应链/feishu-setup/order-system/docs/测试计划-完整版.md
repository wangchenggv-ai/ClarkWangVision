## T-001 草稿缓冲系统

**背景**：提交订单改为存本地 JSON 草稿（~50ms），2 分钟轮询后台同步，草稿满 30 分钟自动同步到 Bitable。代理商追踪页可编辑/取消草稿。

| #        | 测试项           | 步骤                                        | 预期结果                                                  |
| -------- | ------------- | ----------------------------------------- | ----------------------------------------------------- |
| T-001-01 | 提交订单生成草稿      | order.html 提交一笔完整订单                       | 返回 ~50ms（非 Bitable 写入耗时），response 含 draftId           |
| T-001-02 | 草稿持久化         | 提交后重启 docker 容器                           | 草稿不丢失，重启后仍存在（Docker volume `/opt/gaush-lab/drafts/`）  |
| T-001-03 | 草稿轮询同步        | 提交草稿后等待 2-4 分钟                            | 草稿在 2min 轮询窗口内被同步到 Bitable，生成订单编号 ORD-YYYYMMDD-XXXXXX |
| T-001-04 | 30min 编辑窗口内修改 | 提交后 15min，track.html 编辑草稿参数（如顾客姓名、处方 SPH） | 修改成功，草稿 JSON 更新                                       |
| T-001-05 | 30min 编辑窗口内取消 | 提交后 10min，track.html 取消草稿                 | 草稿删除，不写入 Bitable，不生成订单                                |
| T-001-06 | 超 30min 自动同步  | 提交草稿后不操作，等待 30min+                        | 草稿自动同步到 Bitable，订单生成，同步后草稿标记为 synced                  |
| T-001-07 | 超 30min 后编辑拒绝 | 草稿已同步后尝试编辑                                | 编辑被拒绝或提示"已过期"                                         |
| T-001-08 | 并发提交多笔草稿      | 3 个代理商同时各提交 3 笔订单                         | 每笔独立草稿文件，互不干扰，各自按时间独立同步                               |
| T-001-09 | 草稿文件格式完整性     | 提交后检查 `/opt/gaush-lab/drafts/` 下的 JSON    | 字段完整（patients, token, terminalCustomer 等），JSON 合法     |
