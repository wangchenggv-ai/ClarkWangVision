# 计划：根据流程图完善标签打印和发货流程

## 背景

同事画了仓管员+代理商双视角流程图（见飞书文档），对比当前系统，有 4 个主要 gap 需要补齐。

## 流程图关键节点 vs 现状

| 流程图（仓管员） | 现状 | 差距 |
|---|---|---|
| ① 从系统中导出Excel表 | `batch-zip` 导出 Excel 已有 | 未与仓库拣货场景打通——需加"导出拣货单"入口 |
| ② 根据Excel表分拣镜片→有货→打印标签 | 扫码即打 + 批量打印已有 | 无库存有货/缺货标记，拣货效率低 |
| ③ 确认标签打印完成 | 打印队列 `/done` 自动推进 `labeled` | ✅ 已实现 |
| ④ 生成随货同行单 | 发货后弹窗有按钮 | 时机不对——应在**打包**环节生成，而非发货后 |
| ⑤ 打包发快递 | `POST /api/admin/ship` 直接发货 | 跳过了"打包"步骤，flowchart 里打包和发货是两步 |
| ⑥ 记录快递单号 | ship 自动生成快递单号 | ✅ 已实现 |

| 流程图（代理商） | 现状 | 差距 |
|---|---|---|
| 确认收货地址/收货人/处方信息 | ship-preview 弹窗已显示 | 信息在一行灰色小字中，不够醒目 |
| 确认收货 → 完成订单 | `deliver` → 待签收 → webhook 已签收 | ✅ 已实现 |

## 改动计划（4 项）

### 1. ship-preview 弹窗强化收货信息展示

**文件：** `public/labels.html` `shipOrders()` (line 2036-2038)

**现状：** 收货信息（联系人/电话/地址）挤在一行灰色小字里：
```
代理商名 · 联系人 电话 · 地址
```

**改为：** 收货信息单独一个区块，用图标+分行显示，和处方表同等醒目：
```
┌─ 收货信息 ──────────────────────┐
│  联系人：张三                     │
│  电话：138xxxx                    │
│  地址：北京市朝阳区xxx            │
│  备注：（如有）                    │
└─────────────────────────────────┘
```

仓管员核对地址后再点确认发货——对齐流程图"确认订单内容"环节。

### 2. 打包步骤独立：ship 拆为"打包" + "发货"两步

**现状：** `POST /api/admin/ship` 一步到位：状态 `生产中 → 已发货`，工作流 `→ shipped`。

**改为：** 新增 `POST /api/admin/pack` 端点，ship 流程变为两步：

| 步骤 | API | 状态变更 | 工作流 |
|------|-----|---------|--------|
| 打包 | `POST /api/admin/pack` | 不变（仍为"生产中"） | `labeled → packed` |
| 发货 | `POST /api/admin/ship` | `生产中 → 已发货` | `packed → shipped` |

**关键约束：**
- `ship` 的状态守卫从"仅生产中可发货"改为"仅生产中可发货"（保持不变，打包不改状态字段）
- 打包步骤纯工作流推进，不影响订单状态机
- 打包时自动生成随货同行单链接（对齐流程图④的时机）

**文件改动：**
- `server.js`：新增 `POST /api/admin/pack` 端点（~30 行），推进工作流到 `packed`
- `server.js`：`POST /api/admin/ship` 内增加 packed 前置检查（如果已有 packed 步骤则直接推 shipped；如果没有则自动补 packed，保持向后兼容）
- `public/labels.html`：`getQuickAction()` 生产中行新增"打包"按钮（标签打印完成后出现）
- `public/labels.html`：新增 `packOrders()` 函数

**labels.html 行操作变更：**

| 状态 | 现有按钮 | 新增 |
|------|---------|------|
| 生产中（未打包） | 导出、🖨、发货 | + 打包 |
| 生产中（已打包） | 导出、🖨、发货 | （打包按钮变灰/隐藏） |

实际判断逻辑：查工作流步骤，如果已有 `packed` 则不显示打包按钮，直接显示发货。

### 3. 导出拣货单增强

**文件：** `public/labels.html` `getQuickAction()` (line 1721)

**现状：** 生产中行有"导出"按钮，调 `batch-zip` 下载 Excel。

**改为：** 按钮文案改为"拣货单"，功能不变（仍导出 Excel），让仓管员一眼知道这个按钮是干什么的。

**可选增强（视需要）：** `buildFactoryExcel()` 中增加一列"库存状态"（有货/缺货），从 stock_detail 查当前库存标注。这个改动较大，作为 P2。

### 4. 发货完成弹窗优化

**文件：** `public/labels.html` `shipOrders()` (line 2059-2065)

**现状：** 发货完成后显示"生成随货同行单"按钮。

**改为：** 由于同行单已在打包步骤生成，发货完成弹窗改为显示发货结果摘要（快递公司+单号），并提供"复制单号"快捷操作。

## 改动优先级

| 优先级 | 改动 | 理由 |
|--------|------|------|
| P0 | ① ship-preview 收货信息展示强化 | 对齐流程图核心环节"确认订单内容" |
| P0 | ② 打包步骤独立 | 对齐流程图 ③④⑤ 三个独立节点 |
| P1 | ③ 拣货单文案 | 零成本改动，提升仓管员体验 |
| P1 | ④ 发货完成弹窗 | 随打包步骤联动清理 |
| P2 | ③+ 库存状态列 | 需要额外 API 调用，后续迭代 |

## 文件变更清单

| 文件 | 改动内容 |
|------|---------|
| `server.js` | +`POST /api/admin/pack` 端点；`ship` 增加 packed 兼容检查 |
| `public/labels.html` | `shipOrders()` 预览弹窗收货信息重写；新增 `packOrders()`；`getQuickAction()` 加打包按钮+导出改名；发货完成弹窗简化 |

## 不改的部分（确认）

- 不改状态机（5 状态不变：待处理→生产中→已发货→待签收→已签收）
- 不改打印队列逻辑
- 不改随货同行单模板
- 不改工作流步骤定义（STEP_ORDER 不变）
