# 订单 E2E 全流程说明

> 最后更新：2026-04-27

---

## 流程总览

```
代理商下单 → 助理确认（查库存+选供应商）→ 助理发货（有库存则扣库存）→ 助理签收 → 快递回调已签收
  待处理    →      生产中           →       已发货       →    待签收   →    已签收
```

---

## 一、代理商下单

**入口：** `https://lab.gaushclear.com/order?t={代理商Token}`

### 1.1 页面操作

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 选择终端客户 | 下拉选择或新建，自动填充联系人/电话/地址 |
| 2 | 添加顾客 | 点"添加顾客"卡片，输入姓名 |
| 3 | 选择产品型号 | 下拉选择 SKU（Ultra双效/D8/时空之眼A/B/PRO/MAX/小旋风） |
| 4 | 输入度数 | 每只眼输入 SPH/CYL/AXIS，勾选眼别 |
| 5 | 选择数量 | 输入配镜副数 |
| 6 | 选择是否装配 | 默认"否" |
| 7 | 填写备注 | 可选 |
| 8 | 点"提交订单" | 生成订单号+镜片码+QR |

### 1.2 后端流程 (`POST /api/submit`)

```
代理商浏览器                    服务端                           飞书 Bitable
    │                            │                                  │
    ├─ POST /api/submit ────────→│                                  │
    │                            ├─ 幂等检查（clientRequestId）       │
    │                            ├─ 验证代理商 token                 │
    │                            ├─ 验证必填字段                     │
    │                            ├─ 生成订单号 ORD-YYYYMMDD-XXXXXXXX │
    │                            ├─ 写订单主表（1患者=1行）──────────→│ 状态=待处理
    │                            ├─ 写镜片明细表（1眼=1行）─────────→│ 生成16位HEX镜片码
    │                            ├─ 生成QR码图片 → public/qrcodes/  │
    │                            ├─ 发飞书通知                       │
    │←─ 返回订单号+明细 ─────────┤                                  │
```

### 1.3 数据写入

**订单主表**（一患者一条）：

| 字段 | 值 |
|------|-----|
| 订单编号 | `ORD-YYYYMMDD-XXXXXXXX` |
| 订单状态 | `待处理` |
| 产品型号 | SKU 名称 |
| 数量 | 副数 × 眼数 |
| 顾客姓名 | 配镜人 |
| 序号 | 第几副（默认1） |
| 代理商名称/ID | 自动填充 |
| 收货地址/联系人/电话 | 终端客户信息 |
| 是否装配 | 是/否 |
| 订单来源 | 代理商门户 |

**镜片明细表**（一眼一条）：

| 字段 | 值 |
|------|-----|
| 镜片码(唯一) | 16位大写HEX，终生不变 |
| 订单编号 | 关联订单主表 |
| 眼别 | 右眼/左眼 |
| 球镜SPH / 柱镜CYL / 轴位AXIS | 处方数据 |
| 产品型号 / 顾客姓名 / 序号 | 同主表 |
| 订单状态 | `待处理` |

### 1.4 注意事项

- **幂等保护**：`clientRequestId` 必填，10分钟内重复提交返回同一订单号
- **镜片码终生不变**：一旦生成绝不允许回写/重新生成
- **库存不在下单时扣减**：库存仅影响交期判定，在发货时才扣减
- **提交速度 ~3.5秒**（缓存命中后）

## 二、助理确认订单

**入口：** `https://lab.gaushclear.com/labels?admin={ADMIN_TOKEN}`

### 2.1 页面操作

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 找到"待处理"订单 | 可按状态/代理商/日期/关键词筛选 |
| 2 | 点 ▶ 展开详情 | 显示处方表格 + 每只眼库存量 |
| 3 | 系统自动查库存 | 展开时自动调用库存查询 API，显示每只眼库存状态 |
| 4 | 确认库存状态 | 下拉选择：有库存 / 需生产（系统预填，可覆盖） |
| 5 | 确认供应商 | 下拉选择：九次方/圣谱/欧陆（仅需生产时预填，有库存时不填） |
| 6 | 点"确认"按钮 | 状态变为"生产中"，生成镜片码 |

### 2.2 后端流程

**Step A：库存查询** (`GET /api/admin/order-stock-check`)

展开详情时自动调用：

```
服务端                              飞书 Bitable
  │                                    │
  ├─ 查镜片明细表（该订单的所有眼）────→│ 返回 SKU/SPH/CYL
  │                                    │
  ├─ 对每只眼查 stock_detail 表 ──────→│ 查询当前库存
  │  （单条查询 ~200ms，非全表扫描）    │
  │                                    │
  ├─ 判断库存状态：                     │
  │  全部眼有库存 → "有库存"            │
  │  任一眼无库存 → "需生产"            │
  │  超常规范围   → "需生产"            │
  │                                    │
  ├─ 查 supplier_map 配置              │
  │  需生产 → 推荐供应商               │
  │  有库存 → 不推荐（已在仓库）        │
  │                                    │
  └─ 返回结果给前端                     │
```

**Step B：确认** (`POST /api/admin/confirm`)

```
助理浏览器                      服务端                           飞书 Bitable
    │                            │                                  │
    ├─ POST /api/admin/confirm ─→│                                  │
    │                            ├─ 状态守卫（仅"待处理"可确认）      │
    │                            ├─ 生成镜片码（幂等，已有则跳过）    │
    │                            ├─ 更新订单主表 ──────────────────→│ 订单状态=生产中
    │                            │                                  │ 库存状态=有库存/需生产
    │                            │                                  │ 供应商厂家=xxx（如有）
    │                            │                                  │ 镜片码=xxx
    │                            ├─ 更新镜片明细表 ────────────────→│ 镜片码+订单状态=生产中
    │                            ├─ 推进工作流步骤                   │
    │                            │   submitted → confirmed → producing│
    │←─ 返回成功 ────────────────┤                                  │
```

### 2.3 库存状态逻辑

| 情况 | 库存状态 | 供应商 | 说明 |
|------|---------|--------|------|
| 全部眼有库存 | 有库存 | 不指定 | 已在仓库，不需要供应商 |
| 任一眼无库存 | 需生产 | 按SKU映射推荐 | 需要工厂生产 |
| 超常规度数范围 | 需生产 | 按SKU映射推荐 | SPH<-6 或 CYL<-2 |

### 2.4 供应商映射配置

配置文件：`rules_config.json` 的 `supplier_map` 段

```json
{
  "Ultra双效": { "in_stock": "九次方", "out_of_stock": "九次方" },
  "D8": { "in_stock": "圣谱", "out_of_stock": "圣谱" },
  "时空之眼A": { "in_stock": "欧陆", "out_of_stock": "欧陆" },
  "时空之眼B": { "in_stock": "欧陆", "out_of_stock": "欧陆" },
  "时空之眼PRO": { "in_stock": "欧陆", "out_of_stock": "欧陆" },
  "时空之眼MAX": { "in_stock": "欧陆", "out_of_stock": "欧陆" },
  "小旋风": { "in_stock": "九次方", "out_of_stock": "九次方" }
}
```

### 2.5 注意事项

- **仅"待处理"状态可确认**，其他状态会被拒绝
- **镜片码生成是幂等的**：重复确认不会覆盖已有镜片码
- **库存状态和供应商可覆盖**：助理可修改系统预填的值
- **批量确认**：勾选多个订单 → 点"确认订单" → 逐单处理

## 三、助理发货

### 3.1 页面操作

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 找到"生产中"订单 | 可筛选 |
| 2 | 点"发货"按钮 | 弹出确认窗口 |
| 3 | 选择快递公司 | 顺丰/中通/韵达/京东（系统默认顺丰） |
| 4 | 确认发货 | 自动生成快递单号，状态变更为"已发货" |
| 5 | 查看随货同行单 | 发货后可生成/打印同行单 |

### 3.2 后端流程 (`POST /api/admin/ship`)

```
助理浏览器                      服务端                           飞书 Bitable
    │                            │                                  │
    ├─ POST /api/admin/ship ────→│                                  │
    │                            ├─ 状态守卫（仅"生产中"可发货）      │
    │                            ├─ 选择快递公司+生成快递单号         │
    │                            │                                  │
    │                            ├─ [如有库存] 扣减库存 ────────────→│ stock_detail: 当前库存-1
    │                            │   withLock(SKU|SPH|CYL)          │ 写 stock_movement 流水
    │                            │   fresh read → 扣减 → PATCH      │
    │                            │   扣至0不阻断，照常发货            │
    │                            │                                  │
    │                            ├─ 更新订单主表 ──────────────────→│ 订单状态=已发货
    │                            │                                  │ 物流公司/快递单号/发货时间
    │                            ├─ 同步镜片明细表状态 ────────────→│ 订单状态=已发货
    │                            ├─ 推进工作流：packed → shipped     │
    │                            ├─ 发飞书发货通知卡片               │
    │←─ 返回快递单号 ────────────┤                                  │
```

### 3.3 库存扣减逻辑

| 库存状态 | 发货时动作 | 说明 |
|---------|-----------|------|
| 有库存 | 自动扣减 stock_detail + 写 stock_movement 出库流水 | 每只眼扣1片 |
| 需生产 | 不扣库存 | 库存在生产完成后由 rule14 自动回补 |

**扣减细节：**
- 使用 `withLock(key)` 并发锁，防止超卖
- 锁内 fresh read 单条记录（不读全表）
- 扣至 0 不阻断发货
- 写入 `stock_movement` 表：类型=出库，来源=订单发货，关联单号=订单号
- 扣减失败不阻断发货（库存是记录，物流是核心）

### 3.4 快递公司规则

| 代理商 | 默认快递 |
|--------|---------|
| AG-003, AG-006 | 顺丰 |
| AG-005 | 中通 |
| 其他 | 顺丰 |

快递单号格式：`SF/75/YD/JD` + 12位数字

### 3.5 注意事项

- **仅"生产中"状态可发货**
- **扣库存失败不阻断发货**：物流优先，库存记录可人工补
- **幂等保护**：重复发货会因状态守卫被拒绝
- **工作流自动补 packed 步骤**：如果之前跳过了打包步骤

| 2 | 点"拣货单"按钮（单行） | 导出该订单的 Excel |
| 3 | 或点底部"批量导出"按钮 | 导出所有选中订单的合并 Excel |
| 4 | 浏览器自动下载 .xlsx 文件 | |

### 5.3 Excel 内容

| 列 | 说明 |
|----|------|
| 订单编号 | ORD-XXXXXXXX |
| 顾客姓名 | 配镜人 |
| 产品型号 | SKU |
| 数量 | 片数 |
| 眼别 | R/L |
| SPH | 球镜 |
| CYL | 柱镜 |
| AXIS | 轴位 |
| 镜片码 | 16位HEX |
| 是否装配 | 是/否 |
| 联系人 | 收货联系人 |
| 电话 | 联系电话 |
| 收货地址 | 收货地址 |
| 备注 | 每个顾客的特殊要求 |

### 5.4 后端流程 (`GET /api/admin/batch-zip`)

```
助理浏览器                      服务端                           飞书 Bitable
    │                            │                                  │
    ├─ GET /api/admin/batch-zip →│                                  │
    │  ?orderNos=ORD-1,ORD-2    ├─ 查订单主表（联系人/地址/数量）    │
    │  &customer=张三,李四        ├─ 查镜片明细表（度数/镜片码）─────→│
    │                            ├─ buildFactoryExcel()             │
    │                            │  按 orderNo|customerName 分组    │
    │                            │  每组独立信息（联系人/地址/备注）  │
    │                            ├─ 生成 .xlsx buffer              │
    │←─ 返回 Excel 文件 ─────────┤                                  │
```

### 5.5 注意事项

- **按顾客维度导出**：同订单多顾客时，每个顾客独立一行
- **数量从订单主表读取**：不从镜片明细表取默认值
- **备注只取订单主表字段**：不拼接系统信息
- **导出后工厂可直接按 Excel 生产**

## 六、标签打印

### 6.1 用途

每只眼一张标签，贴在镜片包装上。标签包含条形码（订单号）、QR验真码、处方数据、产品型号、顾客姓名。

### 6.2 标签格式（75mm × 40mm）

```
┌──────────────────────────────────────────────┐
│  ▮▮▮▮ Code128 条形码（订单号）▮▮▮▮▮▮▮▮▮▮▮   │
│  时空之眼PRO     顾客姓名       ┌─────────┐ │
│  R 右眼                          │ QR code  │ │
│  SPH     CYL     AXIS            └─────────┘ │
│  -3.00   -1.25    180                        │
│  ABCDEF1234567890       AG-001 测试代理商     │
└──────────────────────────────────────────────┘
```

### 6.3 两种打印方式

| 方式 | 适用场景 | 操作 |
|------|---------|------|
| 浏览器打印 | 普通打印机 + 不干胶纸 | 点 🖨 按钮 → 浏览器打印窗口 |
| 斑马打印 | ZPL 标签打印机 | 点 🖨 按钮 → 入队 → pull-print.js → TCP 斑马打印机 |

### 6.4 页面操作

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 单行打印 | 点该行的 🖨 按钮 |
| 2 | 批量打印 | 勾选多行 → 点底部"批量打印标签" |
| 3 | 扫码打印 | 扫码枪扫条形码 → 自动入队打印 |
| 4 | 浏览器预览 | 打印前可预览标签内容 |

### 6.5 后端流程

**浏览器打印** (`GET /api/admin/labels/print`):
```
浏览器 → 请求可打印 HTML → 服务端查镜片明细+生成标签HTML → 浏览器 print()
```

**斑马打印** (`POST /api/admin/print-queue`):
```
浏览器 → 入队(ZPL) → pull-print.js 每2s拉取 → TCP:9100 → 斑马打印机
```

### 6.6 工作流联动

- 打印完成后自动推进工作流步骤 → `labeled`（标签已打印）
- 批量打印时，所有标签完成后统一推进

### 6.7 注意事项

- **每只眼独立一张标签**（左眼/右眼分开包装）
- **标签包含 QR 验真码**：消费者扫码可验真
- **条形码为 Code128 格式**：扫码枪可识别
- **斑马打印需 pull-print.js 守护进程运行**：在本地打印电脑执行 `node pull-print.js`

## 七、随货同行单

### 7.1 用途

随货同行单是随包裹一起发给客户的单据，包含处方明细、收货信息、产品汇总。客户收到货后核对使用。

### 7.2 页面操作

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 单张同行单 | 已发货/待签收行点 📄 按钮 → 新窗口打开 |
| 2 | 批量同行单 | 勾选多行 → 点底部"同行单"按钮 |
| 3 | 打印 | 浏览器打印（A4 纸） |

### 7.3 同行单内容

| 区域 | 内容 |
|------|------|
| 标题 | 随货同行单 |
| 收货信息 | 联系人、电话、收货地址 |
| 订单信息 | 订单号、代理商、日期 |
| 处方表格 | 眼别、SKU、SPH、CYL、AXIS、镜片码 |
| 订单汇总 | 按 SKU 聚合片数 |
| 备注 | 客户特殊要求 |

### 7.4 后端流程

**单张** (`GET /api/admin/slip/:orderNo`):
```
浏览器 → 服务端查订单+镜片明细 → 生成 A4 HTML → 浏览器 print()
```

**批量** (`GET /api/admin/slip-batch`):
```
浏览器 → 按顾客+收货地址分组 → 每组一张同行单 → 汇总卡片页
```

### 7.5 分组逻辑

- 按 **顾客姓名 + 收货地址** 分组
- 同一顾客同一地址的所有订单合并一张同行单
- 每人镜片按 眼别排序（右眼在上，左眼在下）

### 7.6 注意事项

- **同行单与发货联动**：发货后才可生成
- **待签收/已签收状态也可查看**
- **批量同行单支持按日期筛选**

## 八、消费者验真

**入口：** `https://lab.gaushclear.com/verify/{16位镜片码}`

### 5.1 流程

```
消费者扫码 → GET /verify/{镜片码}
  → 查镜片明细表（镜片码 → 订单编号）
  → 查订单主表（订单编号 → 产品/客户/日期）
  → 显示验真结果：产品型号、顾客姓名、创建时间、处方信息
```

### 5.2 注意事项

- **公开访问，无需登录**
- **显示当前扫码时间**（非订单创建时间）
- **同名客户不同处方**：过滤条件必须加产品型号（`customerName + sku`）

## 九、状态流转总览

```
待处理 ──→ 生产中 ──→ 已发货 ──→ 待签收 ──→ 已签收
  │          │          │          │          │
  │ 确认     │ 发货     │ 标记签收  │ 快递回调  │
  │          │          │          │ 自动     │
  ↓          ↓          ↓          ↓          ↓
submitted  producing  shipped   received   (终态)
  → confirmed            → packed
```

**单向不可逆**：禁止回退状态。如需订正，走单独流程。

**工作流 8 步**（叠加在 4 状态之上）：

| 步骤 | 代码 | 触发时机 |
|------|------|---------|
| 已下单 | submitted | 下单时自动写入 |
| 已确认 | confirmed | 助理确认时 |
| 生产中 | producing | 助理确认时 |
| 质检完成 | qc_done | 助理手动推进 |
| 标签已打印 | labeled | 打印完成后自动 |
| 已打包 | packed | 助理手动或发货时自动补 |
| 已发货 | shipped | 助理发货时 |
| 待签收 | received | 助理标记签收时 |
