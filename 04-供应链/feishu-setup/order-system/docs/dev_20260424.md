# 2026-04-24 开发效率提升：关键改动记录

## 一、Schema 守卫（check_schema.js）

**缘由：** 字段名是硬编码在代码里的字符串，和 Bitable 实际字段一旦不一致就静默失败（FieldNameNotFound）。之前 `automations.js` 的模具表 4 个字段名全部写错，直到跑 E2E 才发现。

**方案：** 新建 `check_schema.js`，定义 16 张表的期望字段列表，运行时调飞书 API 获取实际字段，diff 后报错。CI 也跑这个，任何字段漂移在 push 时就拦截。

```bash
node check_schema.js          # 本地跑
# CI 自动跑，失败时飞书通知
```

## 二、字段修复

**问题：** automations.js 写模具表的 4 个字段名与 Bitable 实际字段不匹配。

| 代码写 | Bitable 实际 |
|--------|-------------|
| `模芯编号` | `模具编号` |
| `总寿命（次）` | `总寿命` |
| `已使用次数` | `已使用` |
| `剩余次数` | `剩余寿命` |

**修复：** `automations.js` 全量替换。以后新增字段名先查 `check_schema.js` 的 EXPECTED_FIELDS。

## 三、测试整合（test.mjs）

**缘由：** 测试脚本散落一地（test_*.js、e2e_*.mjs、check_*.js），没有统一入口，新人不知道该跑哪个。

**方案：** 新建 `test.mjs`，按标签分类管理：

```bash
node test.mjs              # 全部本地测试
node test.mjs schema       # 只跑字段守卫
node test.mjs e2e          # 只跑 E2E
node test.mjs stock        # 只跑库存并发
node test.mjs --cloud      # 本地+云端
```

5 个过时脚本移入 `tests/archive/`（不删，备查）。

## 四、CI 自动化（GitHub Actions）

**缘由：** 改了 Bitable 字段名或表结构，本地忘记跑 check_schema.js，push 后才发现问题。

**方案：** `.github/workflows/ci.yml`（仓库根目录），push 到 main/feat/* 自动触发：
1. checkout → node 20
2. 写 `.env`（从 GitHub Secrets 读飞书凭证）
3. 跑 `check_schema.js`
4. 失败时飞书群发通知卡片

**踩坑：**
- workflow 文件必须在仓库根目录 `.github/workflows/`，子目录的不会触发
- GitHub PAT 需要 `workflow` scope 才能推送 workflow 文件
- `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 忘了加到 GitHub Secrets → CI 全红 → 补上后通过

## 五、E2E 测试修复

**问题：** `e2e_full_sim.mjs` 下单返回 400 "缺少 clientRequestId"。

**原因：** 库存并发安全改造后，`/api/submit` 要求 `clientRequestId` 做幂等保护。

**修复：** 测试 payload 加 `clientRequestId: \`e2e-${Date.now()}\``。
