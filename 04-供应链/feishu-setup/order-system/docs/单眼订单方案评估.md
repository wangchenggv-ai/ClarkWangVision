# 单眼订单方案评估

## 背景

单眼订单（只配一只眼）在现有系统中与双眼订单共用 order.html，需要 uncheck 一只眼才能提交。用户希望简化这个流程。

## 方案对比

| | A. 新建独立页面 | B. 现有页面加模式切换 |
|---|---|---|
| 开发量 | 大（~500 行新页面） | 小（~50 行改动） |
| 维护成本 | **高**（两套页面，改功能要同步） | **低**（一套代码） |
| 用户体验 | 清晰，入口明确 | 需要切换模式 |
| 代理商学习成本 | 需要知道两个入口 | 同一页面自然发现 |
| BUG 风险 | 低（互不影响） | 中（改现有页面可能回归） |
| 后端改动 | 需加路由 | 零改动 |

## 建议：B. 现有页面加模式切换

理由：
1. 单眼订单量小，不值得维护一整套新页面
2. 改动量小，风险可控
3. 后端零改动，复用所有现有流程
4. 未来改功能只改一处

## 具体方案

### order.html 改动（~50 行）

1. **页面顶部加 toggle**：在地址栏下方加"单眼下单"开关
2. **切换逻辑**：
   - 开启：隐藏左眼输入区，只保留右眼；眼别下拉改为可选（右眼/左眼）；数量标签从"副"改为"片"
   - 关闭：恢复双眼模式，两只眼都显示
3. **提交逻辑不变**：`collectPatients()` 已经动态处理 eyes 数组长度

### 同时修复的 BUG（3 处）

1. **通行单 eye fallback**（server.js ~line 3706）：空眼别不猜，显示"—"
2. **templates.js slipHTML eyeRow**：三态判断，未知眼别显示"—"
3. **order.html 提交校验**：两眼都取消时已有 toast 提示（line 741，已存在）

## 涉及文件

| 文件 | 改动量 | 内容 |
|------|--------|------|
| `public/order.html` | ~50 行 | 加单眼模式 toggle + 切换逻辑 |
| `server.js` | 1 行 | slip eye fallback |
| `lib/templates.js` | 1 行 | eyeRow 三态 |

## 验证

1. 切换到单眼模式，选左眼，填度数，提交
2. 检查 Bitable：订单数量=1，镜片明细 1 条，眼别=左眼
3. 走 confirm → 打标签 → 发货 → 通行单，确认通行单显示正确眼别
