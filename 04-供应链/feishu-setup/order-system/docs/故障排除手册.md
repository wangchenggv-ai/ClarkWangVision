## 一、飞书 Bitable API 问题

### 1.1 订单列表显示 5000 条（实际几百条）

- **症状**：orders.html 加载后显示数千条记录，远超实际订单数
- **根因**：飞书 `POST /records/search` 分页 bug，`has_more` 永不为 `false`，循环返回同一页数据，searchRecords 跑满 maxPages 导致假记录堆叠
- **修复**：`lib/feishu.js` searchRecords 加 `total` 守卫 + `record_id` 去重；`server.js` orders-fast 无筛选时改用 `listRecords`(GET) 绕开 bug
- **文件**：`lib/feishu.js`、`server.js`
- **日期**：2026-05-23

### 1.2 FieldNameNotFound (code=1254045)

- **症状**：写入 Bitable 报错，日志出现 `FieldNameNotFound (1254045)`
- **根因**：代码写入了 Bitable 中不存在的字段（如 `单价`/`金额`/`终端门店`/`镜片码状态`）
- **修复**：移除不存在字段的写入；或在 Bitable 中补建对应字段
- **排查**：检查 `shared/tables.js` 中表 ID 是否正确；对比代码中的字段名与 Bitable 实际字段
- **文件**：`server.js`、`shared/tables.js`
- **日期**：2026-05-23

### 1.3 RecordIdNotFound (1254043)

- **症状**：删除或更新记录时报 `RecordIdNotFound`
- **根因**：record_id 不存在（已删除、迁移数据、或批量操作中部分失败）
- **修复**：先用 GET 确认 record_id 存在；批量操作加 try-catch 跳过不存在的记录
- **文件**：`lib/feishu.js`

### 1.4 草稿同步失败（FieldNameNotFound 根因）

- **症状**：代理商提交订单后，追踪页显示"同步失败"红色警示
- **根因**：`processPendingDrafts` 写入 Bitable 时字段不匹配（订单主表缺 `单价`/`金额` 字段）
- **修复**：移除不存在字段的写入；Fix1-5 系列修复（幂等检查、缓存刷新、失败标记+飞书告警）
- **排查**：检查 `/api/admin/retry-draft` 端点日志；查看 `syncFailed` 标记
- **文件**：`server.js`、`lib/feishu.js`、`public/track.html`
- **日期**：2026-05-23

### 1.5 tenant_access_token 获取失败 (code 9499)

- **症状**：所有飞书 API 调用失败，日志报 `code 9499`
- **根因**：`shared/.env` 中 `FEISHU_APP_ID`/`FEISHU_APP_SECRET` 配置错误（用了通知应用凭证而非多维表格应用凭证）
- **修复**：确认 `.env` 中是正确的应用凭证（`cli_a94dfd3512f9dbd9`）
- **文件**：`shared/.env`
- **日期**：2026-04-16

### 1.6 重复记录（20 倍堆叠）

- **症状**：Bitable 订单主表出现大量重复记录
- **根因**：`processPendingDrafts` 无幂等检查 + 飞书 API 10s 超时（数据已写入但返回超时）→ 重试 → 重复写入
- **修复**：已加幂等检查（URL 编码 + record_id 去重）；超时从 10s 改为 15s
- **清理**：使用 `dedup_orders.mjs` 脚本清理（dry-run 先验证）
- **文件**：`server.js`、`lib/feishu.js`
- **日期**：2026-05-22

## 二、订单状态流转问题

### 2.1 镜片码未生成（状态被直接改到打标签）

- **症状**：订单状态直接变为"打标签"但没有镜片码，验真失败
- **根因**：通过 `update-field` 直接改状态跳过了 confirm 流程（confirm 才生成镜片码）
- **修复**：调飞书 API 手动为该订单生成镜片码并写入两表；或用 `/diagnose?admin=GaushOrderMock` 诊断+修复
- **排查**：检查 lens_detail 表是否有该订单的镜片码记录
- **文件**：`server.js`
- **日期**：2026-05-14（补码案例）

### 2.2 打标签退回失败

- **症状**：打标签状态的订单点退回无反应
- **根因**：`labels.html` 的 `revertOrder` 函数中 `REVERT_MAP` 缺少 `"打标签": "已下单"` 映射
- **修复**：补全 REVERT_MAP
- **文件**：`public/orders.html`（原 labels.html）
- **日期**：2026-04-28

### 2.3 镜片码找不到（lens_detail 缺记录）

- **症状**：扫码打印时提示"镜片码未找到"，129 条镜片码在订单主表有但 lens_detail 无记录
- **根因**：旧迁移数据绕过 confirm 端点，未在 lens_detail 表创建记录
- **修复**：运行 `migrate_lens_detail.js` 补建缺失记录
- **文件**：`migrate_lens_detail.js`
- **日期**：2026-04-28

### 2.4 废弃状态残留（待签收/已签收）

- **症状**：订单表中存在"待签收"或"已签收"状态
- **根因**：早期状态机设计后被废弃，历史数据未清理
- **修复**：批量更新为"已发货"
- **日期**：2026-04-28

## 三、性能问题

### 3.1 确认订单慢（9-18 秒）

- **症状**：点确认后长时间等待
- **根因**：首次 confirm 时 `getStockMap()` 读全表 stock_detail（~1575 条）耗时 10s+
- **修复**：启动时预热库存缓存；confirm 端点并行读取 + batchUpdate
- **性能**：18s → 5s（预热后）→ 4.5s（并行优化后）
- **文件**：`server.js`、`lib/stock.js`
- **日期**：2026-04-28

### 3.2 提交订单慢（14 秒）

- **症状**：代理商点提交后长时间等待
- **根因**：`/api/submit` 调用 `getStockMap()` 读全表（~1575 条）耗时 10.6s
- **修复**：封存库存扣减逻辑，提交不再读库存表，速度降到 3.5s
- **文件**：`server.js`
- **日期**：2026-04-30

### 3.3 筛选查询慢（5 秒）

- **症状**：订单管理页筛选操作响应慢
- **根因**：原端点拉全表后客户端过滤
- **修复**：新增 `/api/admin/orders-fast` 端点，用飞书 `records/search` API 带 filter（服务端筛选），首次筛选从 ~5s 降到 ~1s
- **文件**：`server.js`、`lib/feishu.js`、`lib/export-log.js`
- **日期**：2026-05-14

### 3.4 交期预估卡顿

- **症状**：下单页输入度数时页面卡顿
- **根因**：每次度数输入都调交期预估 API
- **修复**：交期预估迁移至确认时一次性计算回写，代理商在追踪页查看
- **文件**：`server.js`
- **日期**：2026-04-30

## 四、前端 UI 问题

### 4.1 页面白屏 / JS 崩溃

- **症状**：order.html 或 orders.html 打开后白屏
- **根因**：重复 `const` 声明（同名变量在内联 JS 中出现两次）
- **修复**：`grep` 检查变量名唯一性，删除重复声明
- **排查**：浏览器 Console 看 SyntaxError
- **文件**：`public/order.html`、`public/orders.html`

### 4.2 终端客户列表加载阻塞

- **症状**：下单页打开后长时间空白
- **根因**：`/api/terminal-customers` 同步加载阻塞首屏渲染
- **修复**：改为异步加载且不堵死下单流程
- **文件**：`public/order.html`

### 4.3 扫码输入无响应

- **症状**：labels-print.html 扫码枪输入后无反应
- **根因**：scanBuffer 150ms 超时为扫枪设计，手动输入太慢导致 Enter 时缓冲区已清空
- **修复**：Enter 时 fallback 读 `input.value`
- **文件**：`public/labels-print.html`
- **日期**：2026-04-28

### 4.4 筛选器状态冲突

- **症状**：统计卡与下拉筛选器互相残留状态
- **根因**：`filterStatus` 下拉缺少 `onchange` 重置 `activeStatusFilter`
- **修复**：下拉加 `onchange` 重置 + 卡片高亮
- **文件**：`public/orders.html`
- **日期**：2026-05-10

### 4.5 导出按钮不显示

- **症状**：orders.html 的导出 Excel 按钮消失
- **根因**：重构时误加 `ctx-btn` 类导致按钮默认隐藏
- **修复**：移除 `ctx-btn` 类，按钮始终显示
- **文件**：`public/orders.html`
- **日期**：2026-05-23

### 4.6 确认弹窗无反应（筛选后停在空页）

- **症状**：切换筛选条件后点确认无结果
- **根因**：查询按钮未重置 `currentPage`，停在了不存在的页码
- **修复**：查询按钮加 `currentPage=1`
- **文件**：`public/orders.html`
- **日期**：2026-05-10

### 4.7 导出状态筛选器不生效

- **症状**：选了"已导出工厂"等筛选项但无变化
- **根因**：`filterExport` 缺少 `onchange` 事件绑定
- **修复**：加 `onchange="currentPage=1;loadOrders()"`
- **文件**：`public/orders.html`
- **日期**：2026-05-23

### 4.8 详情表 AXIS 列不对齐

- **症状**：镜片明细表格列宽错配，数据串行
- **根因**：`table-layout:fixed` + `colgroup` 方案不匹配动态内容
- **修复**：改为 `table-layout:auto`，浏览器自动按内容分配列宽
- **文件**：`public/orders.html`
- **日期**：2026-04-28

### 4.9 订单号列宽过窄

- **症状**：订单号被截断显示不全
- **根因**：订单号单行列宽 130px 不够
- **修复**：订单号拆两行（`ORD-YYYYMMDD` / `-XXXXXX`），列宽缩至 90px
- **文件**：`public/orders.html`
- **日期**：2026-04-28

## 五、标签与打印问题

### 5.1 标签内容溢出

- **症状**：标签纸 75×40mm 上内容超出边界
- **根因**：标签内容未缩放
- **修复**：`.label-inner` + `transform:scale(0.8)` 缩到 80%，整体右移 4mm
- **文件**：`lib/templates.js`、`public/labels-print.html`、`print_labels.js`、`lib/printer.js`
- **日期**：2026-05-11

### 5.2 条形码编码格式

- **症状**：工厂扫码无法识别型号和度数
- **根因**：条形码格式不规范
- **修复**：CODE128 条形码，编码格式 `TKAP-250-125`（型号缩写-SPH×100-CYL×100）
- **文件**：`lib/templates.js`、`lib/factory-export.js`
- **日期**：2026-05-13

### 5.3 导出 Excel 后状态未变更

- **症状**：批量导出 Excel 后订单状态仍为"生产中"
- **根因**：`exportExcelSelected()` 导出后未调 `update-field` 流转状态
- **修复**：导出后自动调 `update-field` 将状态改为"打标签"
- **文件**：`public/labels-print.html`
- **日期**：2026-05-12

### 5.4 导出 Excel 跨订单混入

- **症状**：选不同订单的客户时，导出数据跨订单错乱
- **根因**：`customer=Clark,1111` 传给 API 导致跨订单过滤
- **修复**：前端按订单号分组传 `orderCustomers=ORD-A:Clark|ORD-B:1111`，后端按订单号分别过滤
- **文件**：`public/orders.html`、`server.js`
- **日期**：2026-04-28

### 5.5 切换筛选后导出混入旧数据

- **症状**：导出了不属于当前筛选结果的订单
- **根因**：`selectedOrders` 未在切换筛选时清空
- **修复**：`loadOrders()` 开头加 `selectedOrders.clear()`
- **文件**：`public/orders.html`
- **日期**：2026-04-28

## 六、验真系统问题

### 6.1 验真页 404

- **症状**：消费者扫码验真返回 404
- **根因**：验真接口查订单表而非镜片明细表；或 `/verify` 静态路由缺失
- **修复**：改查 `lens_detail` 表；server.js 添加 `/verify` 和 `/verify.html` 静态路由
- **文件**：`server.js`
- **日期**：2026-04-15 / 2026-05-02

### 6.2 QR 码 localhost 问题

- **症状**：手机扫码无法访问（QR 码地址是 localhost）
- **根因**：`shared/.env` 缺少 `SERVER_BASE_URL`，QR 码 fallback 到 localhost
- **修复**：`.env` 添加 `SERVER_BASE_URL=https://lab.gaushclear.com`
- **文件**：`shared/.env`
- **日期**：2026-04-15

### 6.3 验真页同名客户混入

- **症状**：验真结果显示了同名但不同处方的客户数据
- **根因**：按客户名过滤无法区分同名不同处方
- **修复**：过滤条件加产品型号（`customerName + sku`）
- **文件**：`server.js`

### 6.4 OEM 品牌显示错误

- **症状**：验真页面始终显示高视高清品牌（应显示铂视控）
- **根因**：`终端门店` 字段未维护，`getBrandByStoreName("")` 返回默认品牌
- **修复**：维护终端门店字段后，恢复 `applyBrandToHtml()` 代码即可启用
- **文件**：`server.js`、`lib/brand-config.js`
- **日期**：2026-05-23

## 七、部署问题

### 7.1 根路由 404

- **症状**：访问 `lab.gaushclear.com` 返回 404
- **根因**：生产容器缺少 `portal.html`
- **修复**：`docker cp portal.html order-app:/app/public/`
- **日期**：2026-05-02

### 7.2 测试环境容器缺少函数

- **症状**：测试容器报 `batchUpdateRecords is not a function`
- **根因**：测试容器旧镜像未更新 `lib/feishu.js`
- **修复**：重新 scp + docker cp 更新测试容器代码
- **日期**：2026-05-02

### 7.3 采购表报错（TableIdNotFound）

- **症状**：启动时报 `TableIdNotFound` 错误
- **根因**：`tables.js` 中采购表 ID 已注释但 server.js 仍引用

- **文件**：`shared/tables.js`、`server.js`
- **日期**：2026-04-28

### 7.4 部署后文件未生效

## 九、诊断工具

### 9.1 内置诊断端点

```
GET /diagnose?admin=GaushOrderMock&orderNo=ORD-xxx
```

自动检查：
- 订单是否存在
- 镜片明细是否存在
- 镜片码是否生成
- 状态是否一致
- QR 图片是否缺失
- 草稿是否待同步/失败
- 支持直接改状态跳过赋码（update-field）

### 9.2 快速排查清单

| 症状 | 第一步 |
|------|--------|
| 订单消失 | 检查是否在草稿中（`/api/admin/drafts`） |
| 镜片码缺失 | 用 diagnose 确认，必要时手动补码 |
| 页面白屏 | 浏览器 Console 看 JS 错误 |
| API 报错 | 检查 `.env` 配置 + 飞书应用凭证 |
| 部署后无效 | `docker exec` 确认容器内文件版本 |
| 导出数据异常 | 检查 `selectedOrders` 是否残留 + 筛选条件是否正确 |
