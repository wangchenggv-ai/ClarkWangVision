# 三系统数据架构设计文档

**日期：** 2026-04-11  
**状态：** 已确认，待实施

## 目标

在不改动现有运营流程的前提下，将旧订单表、CRM销售飞轮、供应链系统三者数据打通，以终端客户为关联键，支撑供应链9条业务规则的正常运行。

---

## 架构图

```
┌─────────────────────────────────────────────────────┐
│              旧订单表（唯一订单源头，只读）              │
│         飞书多维表，运营团队日常录单，~70单/天          │
└──────────────────────┬──────────────────────────────┘
                       │ 增量同步（各自独立读）
          ┌────────────┴────────────┐
          ▼                         ▼
┌─────────────────┐       ┌─────────────────────┐
│   CRM 销售飞轮   │       │    供应链执行系统     │
│  客户主数据      │◀──客户ID──  终端客户表（镜像）│
│  销售分析        │       │  订单镜像（滚动90天） │
│  拜访/培训记录   │       │  库存/模芯/生产/采购  │
│  5条自动化规则   │       │  9条业务规则          │
└─────────────────┘       └─────────────────────┘
```

**数据流原则：单向，不回写**

---

## 三系统职责

| 系统 | 职责 | 数据所有权 |
|------|------|-----------|
| 旧订单表 | 运营录单，订单全生命周期 | 订单（唯一源头） |
| CRM 销售飞轮 | 客户关系、销售分析、拜访培训 | 客户主数据 |
| 供应链执行系统 | 库存、生产、采购、9条规则 | 生产/库存数据 |

---

## 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 订单源头 | 旧订单表，永不迁移 | 零风险，运营无感 |
| 客户主数据归属 | CRM 拥有 | CRM 已有完整客户档案 |
| 供应链订单范围 | 滚动90天镜像 | Rule1-9 不需要历史全量，防止 Bitable 记录数膨胀 |
| 客户 ID 格式 | `CUS-YYYYMMDD-XXXX`（业务键） | 与飞书 record_id 解耦，未来换平台可直接迁移 |
| 来源订单号 | 旧表原始单号 | 去重 + 跨系统追溯 |
| 同步频率 | 每天定时（初期手动触发） | 70单/天无需实时 |

---

## 同步机制

### 订单同步（旧订单表 → 供应链）

- 脚本：`sync_orders.js`
- 模式：增量（游标记录上次同步时间，存 `.sync_cursor.json`）
- 去重键：`来源订单号`（旧表原始单号）
- 滚动窗口：仅保留最近90天，超期记录归档删除
- 幂等：重跑安全，不产生重复记录

### 客户同步（CRM → 供应链）

- 脚本：`sync_customers.js`（待建）
- 模式：增量（按创建时间游标）
- 匹配键：客户名称（精确匹配）
- 逻辑：CRM 有则同步客户ID，无则供应链侧自动生成

## 扩展性说明

当前架构基于飞书多维表，适用规模：

- 当前：70单/天 ✅
- 2026年目标：200单/天 ✅  
- 2027-2028：500单/天 ⚠️（需关注 Bitable 记录数上限）
- 2029-2030（IPO前）：1000单/天 → 届时自然升级至 ERP 或定制系统

**业务逻辑（9条规则、CRM自动化）与存储层解耦，未来换平台时逻辑可直接迁移。**
