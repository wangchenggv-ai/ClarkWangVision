## 二、设计背景

### 2.1 飞书多维表格新功能（2026）

飞书多维表格发布了一批重大更新，直接影响供应链系统的技术选型：

| 新功能 | 关键能力 |
|---|---|
| AI 生成工作流 | 文字描述需求 → AI 自动搭建工作流 |
| AI 分类节点 | 智能识别文本内容，自动分类并执行对应分支（2-10 分类） |
| AI Agent 节点 | 自主调用工具（发消息、新增记录等），支持自定义 MCP 工具，具备记忆能力 |
| AI 侧边栏 | 自然语言对话查询数据、执行任务 |
| 应用模式 | 拖拽搭建专业级业务系统界面，无需技术背景 |
| 仪表盘升级 | 数据透视表、切片器、图表联动、Top N |
| 数据库升级 | 单表 200 万行，1,000 人同时编辑 |
| 工作流多分支节点 | 根据条件执行 2-10 条分支路径（类似 IFS） |
| 工作流公式支持 | 对流程中的数据/变量进行计算与处理 |
| 按钮触发工作流 | 用户点击按钮 → 执行关联自动化 |
| 飞书消息触发 | 机器人收到群消息 → 自动执行流程 |
| 沙箱 | 完全隔离的测试环境，验证通过后一键上线 |
| 自定义记录详情页 | 自定义布局、标签页、字段展示方式 |
| 80+ 新连接器 | 第三方系统数据同步到多维表格 |

### 2.2 现有系统概况

当前供应链系统基于 **飞书多维表格 + Node.js 脚本**：

- **12 张数据表**：SKU 主数据、成品库存、毛坯库存、模芯管理、订单、排产计划、销售预测、AI 分析记录、采购跟踪、车房产能、售后记录、规则配置
- **9 条业务规则**：`automations.js`（2,100+ 行），配置驱动
- **AI 分析**：`ai_analysis.js` 调用 Coze API 生成周度报告
- **仪表盘**：`dashboard.js` + ECharts（12 KPI、8+ 图表）
- **总代码量**：5,467 行 / 18 文件

## 三、原生化迁移方案

### 3.1 业务规则迁移（automations.js → 飞书工作流）

#### 可完全原生化的 7 条规则

| 规则 | 名称 | 原生实现方案 |
|---|---|---|
| Rule 1 | 订单处理 | **多分支节点**：数量 > 100 → 定制件（交期 5 天）；否则 → 库存件（交期 3 天）。用**公式**计算预计交付日期 |
| Rule 2 | 库存预警 | **记录更新触发** → 公式对比安全库存 → **多分支**（正常 / 低库存 / 缺货）→ 发飞书消息通知 |
| Rule 3 | 模芯预警 | 同上模式。公式判断：剩余寿命 < 50 → 紧急采购；< 500 → 预警提醒 |
| Rule 5 | 毛坯预警 | 公式：当前库存 < 月均用量 × 安全系数(1.5) → 触发采购流程 |
| Rule 6 | 超期预警 | **定时触发**（每小时）+ 公式计算超期小时数 → 多分支通知（> 24h 告警） |
| Rule 7 | 采购触发 | 预警工作流下游节点 → 自动在采购跟踪表新增记录（模芯 lead time 28 天，毛坯 21 天） |
| Rule 9 | 模芯累加 | 订单状态变为"已完成"触发 → 公式累加模芯使用次数 → 更新模芯管理表 |

#### 需脚本辅助的 2 条规则

| 规则 | 名称 | 原生能力 | 脚本补充 |
|---|---|---|---|
| Rule 4 | 排产建议 | 公式可算季节系数（暑期 1.3、春节 0.8），简单排产用多分支 | 多工厂多约束优化 → 脚本算法，通过 **HTTP 请求节点**调用 |
| Rule 8 | 车房分配 | 简单专长加分(+10)用公式可行 | 多约束组合优化（产能、队列、专长、地域）→ 脚本算法 |

### 3.2 AI 分析迁移（ai_analysis.js → AI Agent 节点）

| 现有实现 | 原生替代 |
|---|---|
| Coze API 调用生成周度分析报告 | **AI Agent 节点**：定时触发 → Agent 读取本周订单/库存/交期数据 → 生成分析 → 自动写入 AI 分析记录表 + 发送飞书消息 |
| 脚本中的售后问题分类 | **AI 分类节点**：新增售后记录时自动分类（质量问题 / 物流问题 / 度数问题 / 其他） |
| — | **AI 侧边栏**（新增）：业务人员直接问"本周超期最多的 SKU 是什么""Ultra 库存还够几天" |

### 3.3 仪表盘迁移（dashboard.js → 原生仪表盘）

| 现有 ECharts 图表 | 原生替代方案 |
|---|---|
| SKU 库存状态分布（饼图） | 原生饼图 + **切片器**（按品牌筛选） |
| 交期达成率趋势（折线图） | 原生折线图 |
| 工厂产能利用率（柱状图） | 原生柱状图 + **Top N**（展示利用率最低的车房） |
| SKU × 工厂 交叉分析 | **数据透视表**（行=SKU，列=工厂，值=达成率） |
| 超期订单明细 | 原生表格 + 切片器（按时间范围、品牌筛选） |
| 多图表联动 | **图表联动**：点击某品牌 → 所有图表同步筛选 |
| 12 个 KPI 卡片 | 原生数字卡片 |

**保留 ECharts 的场景**：如需高度定制的复合图表（如甘特图式排产视图），仍用脚本生成嵌入。

### 3.4 通知迁移（notify.js → 原生消息动作）

现有 `notify.js` 通过飞书 webhook 发送通知 → 全部替换为工作流内置的**发送消息**动作。

无需保留任何通知相关脚本。

## 四、保留脚本清单

迁移后保留 **4 个核心脚本**，均通过飞书工作流 HTTP 请求节点调用：

### 4.1 classify_skus.js — ABC-XYZ 分类算法

- **保留原因**：涉及变异系数计算、帕累托分析等统计算法，工作流公式无法胜任
- **调用方式**：月度定时工作流 → HTTP 请求 → 脚本执行 → 结果写回 SKU 主数据表
- **预计代码量**：~300 行

### 4.2 deliver_analysis.js — 7 步自改善引擎

- **保留原因**：7 个 what-if 模拟场景（调整安全库存、切换推拉策略、修改排产系数等），逻辑复杂度超出工作流能力
- **调用方式**：周度定时工作流 → HTTP 请求 → 脚本执行 → 结果写入 AI 分析记录表
- **可优化**：核心模拟保留脚本，报告生成部分交给 AI Agent 节点
- **预计代码量**：~600 行

### 4.3 车房分配优化（从 automations.js 拆出）

- **保留原因**：多工厂 × 多约束（产能上限、队列深度、专长匹配、地域优先）的组合优化
- **调用方式**：排产计划表按钮触发 → HTTP 请求 → 脚本返回最优分配方案
- **预计代码量**：~300 行

### 4.4 migrate_tables.js — 表结构迁移

- **保留原因**：飞书无原生的表结构版本管理方案
- **调用方式**：手动执行（`node migrate_tables.js`）
- **预计代码量**：~300 行（保持现有框架）

## 五、新功能增量应用

以下飞书新功能为系统带来**之前不具备的新能力**：

### 5.1 应用模式 — 一线操作界面

为不同角色搭建专用操作界面（拖拽搭建，无需代码）：

| 角色 | 界面功能 |
|---|---|
| 仓库人员 | 入库登记、库存盘点、毛坯领用 |
| 车房工人 | 今日排产查看、报工完成、异常上报 |
| 销售 | 订单录入、交期查询、客户催单 |
| 管理层 | 仪表盘总览、审批、规则配置调整 |

**价值**：替代之前需要额外开发前端页面的需求，一个应用可关联多个多维表格。

### 5.2 沙箱 — 安全测试环境

- 新规则上线前先在沙箱验证（如修改安全库存系数、调整排产逻辑）
- 所有操作不影响正式数据
- 验证通过后一键同步到生产环境

**价值**：解决之前没有测试环境、规则修改直接影响生产的痛点。

### 5.3 飞书消息触发 — 群内即时查询

配置场景示例：

- 销售在群里发 `查库存 Ultra 1.67` → 机器人自动查表回复库存数量和状态
- 车房主管发 `今日排产` → 机器人返回当日排产计划摘要
- 任何人发 `订单 ORD-20260330-001` → 机器人返回订单状态和预计交期

### 5.4 自定义记录详情页 — 信息卡片

| 表 | 详情页设计 |
|---|---|
| 订单表 | 标签页分组：基本信息 / 生产进度 / 物流信息 / 关联模芯 |
| 模芯管理表 | 核心指标前置：剩余寿命进度条、累计使用次数、预警状态 |
| 采购跟踪表 | 时间线视图：下单 → 生产中 → 发货 → 到货 |

### 5.5 200 万行支持

- 历史订单数据不再需要定期归档清理
- 全量数据保留，支撑 AI 分析更长时间维度的趋势
- 按目标 25,000 单/年计算，可保留 80 年数据

## 七、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 工作流公式能力不足以表达某些业务规则 | 迁移受阻 | 利用沙箱充分测试；不足部分退回脚本实现 |
| AI Agent 节点输出不稳定 | 周报质量波动 | 设定 prompt 模板 + 输出格式校验；关键报告人工复核 |
| 原生仪表盘图表类型不够 | 部分图表无法迁移 | 保留 ECharts 做补充，混合展示 |
| HTTP 请求节点调用脚本的延迟 | 用户体验 | 脚本部署在低延迟环境；异步执行 + 完成后通知 |
| 沙箱与生产环境同步时的数据冲突 | 配置覆盖 | 仅同步工作流和配置，不同步业务数据 |
