# 供应链系统开发复盘与计划

**日期：** 2026年4月14日

---

## 一、今日核心决策

三大系统（CRM、订单交付、供应链）**先不打通，分开独立开发**。

**原因：** 三系统耦合开发导致改一个字段需30分钟，规则复杂度远超预期，本地跑通但真实场景大量卡点。

## 二、经验教训

1. **"能跑通"≠"能用"：** 每个模块先用真实数据跑最小闭环，再扩展功能
2. **规则比代码难：** 业务规则必须从真实业务中逐条提炼，规则不清就编码等于在沙子上盖楼
3. **过早集成是最大的坑：** 分开做、分步验证、最后再连接

## 四、订单交付系统开发计划（6.30前）

**核心闭环：** 代理商门户下单 → 数据同步多维表格 → 生成QR Code → 消费者扫码查询订单状态

- **Phase 1（4月底前）：** 代理商下单 → 数据落表，先切通最小闭环
- **Phase 2（5月）：** 多维表格 → QR Code → 消费者扫码查订单
- **Phase 3（6月）：** 异常处理、状态流转完善、边界情况打磨

每个Phase结束做一次真实场景验证。

## 五、顶层设计原则

**三个系统共享编码规则，不共享数据库。**

> 同一本字典，三本独立的账本。将来打通就是账本之间用字典对话。

- 每个系统定义自己的唯一ID格式（订单号、客户编号、SKU编号）
- 约定未来打通时的数据交换格式
- 用共享的"编码规则文档"锁住约定
