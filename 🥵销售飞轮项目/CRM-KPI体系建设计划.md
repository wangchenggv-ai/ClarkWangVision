# CRM KPI 体系建设计划

**创建时间**：2026-04-06  
**项目**：销售飞轮 Feishu Bitable CRM  
**Base**：https://gausheyetech.feishu.cn/base/MSqkbR21kaTO9Ys39qkcv7qzn9b

---

## 目标

把销售和市场的所有行动（拜访、培训、会议）与客户、订单用数字指标打通，实现：
- 培训后1周/30天出单率自动计算
- 销售拜访后7/30天订单归因
- 市场会议ROI自动统计
- 客户从意向到出单周期分析
- 出单稳定性评分（识别活跃/休眠/流失客户）

---

## 一、核心 KPI 体系（6大维度）

| 维度 | 核心指标 | 数据来源 |
|------|---------|---------|
| 培训效果 | 1周出单率、30天出单率、出单金额 | 培训审批表 + 订单表 |
| 销售拜访效果 | 拜访后7/30天订单金额、拜访-出单转化率 | 销售责任上报表 + 订单表 |
| 市场会议效果 | 会后客户增长率、会议ROI（出单额/成本） | 市场会议表 + 订单表 |
| 客户生命周期 | 意向→出单天数、复购周期、出单稳定性 | 终端客户表 + 订单表 |
| 销售绩效 | 人均订单额、人均客户数、管道转化率 | 销售上报表 + 客户表 + 订单表 |
| 行动-订单关联 | 每个行动对应的订单归因 | 全部7张表 |

## 四、新增自动化规则（rule6-rule9）

在 `flywheel-automations/automations.js` 中扩展：

| 规则 | 触发频率 | 计算内容 |
|------|---------|---------|
| rule6 | 每日凌晨 | 扫描销售上报表，计算拜访后7/30天出单金额回写 |
| rule7 | 每日凌晨 | 扫描会议主表，计算会后30天出单额回写，更新ROI |
| rule8 | 每日凌晨 | 计算客户意向→出单天数、出单稳定性评分回写客户表 |
| rule9 | 每周一 | 生成行动效率摘要，推送飞书消息给管理层 |

### rule6 逻辑（拜访效果）
```
for 每条销售上报记录:
  拜访日期 = record.拜访日期
  客户ID = record.关联客户
  7天窗口订单 = 订单表.filter(客户=客户ID, 订单日期 in [拜访日期, 拜访日期+7d])
  回写: 拜访后7天出单金额, 归因订单数
  同理计算30天窗口
```

### rule7 逻辑（会议效果）
```
for 每个市场会议:
  会议日期 = meeting.会议日期
  参会客户列表 = 客户名单表.filter(所属会议=会议ID)
  for 每个参会客户:
    30天订单 = 订单表.filter(客户=客户ID, 日期 in [会议日期, 会议日期+30d])
    前30天基准 = 订单表.filter(客户=客户ID, 日期 in [会议日期-30d, 会议日期])
  汇总回写: 会后30天总出单额, 更新ROI
```

### rule8 逻辑（客户周期）
```
for 每个客户:
  首次出单 = 订单表.filter(客户=客户ID).min(订单日期)
  最近出单 = 订单表.filter(客户=客户ID).max(订单日期)
  回写: 首次出单日期, 最近出单日期
  
  出单间隔列表 = 相邻订单日期差值数组
  稳定性评分 = 100 - 标准差(出单间隔) 的归一化值
  (若无订单=0, 只有1笔=50, 均匀复购=100)
```

## 七、数据说明

- **归因逻辑**：行动（拜访/培训/会议）发生后N天内，**同一客户**的新订单归因到该行动。若同期有多个行动，订单重复计入（不做分摊，便于管理层看全貌）。
- **出单稳定性**：0-100分。0=从未出单，50=只有1笔，>80=高频稳定，<30=流失风险。
- **会议ROI**：仅统计有出单的客户贡献，不含培训成本（单独在培训表统计）。
